# 国密（SM2/SM3/SM4）改造

> 依据：GB/T 39786-2021《信息系统密码应用基本要求》（密评）。具体改造范围以测评机构与甲方的密码应用方案为准，代码改造前先拿到方案。核对日期：2026-10。

## 先分类，再动手

扫描命中（`SM-*` 规则）后，逐条判断用途：

| 用途 | 是否必须改 | 做法 |
|---|---|---|
| 口令存储 | 通常必须 | SM3 + 盐 + 多轮（或 PBKDF2 以 HMAC-SM3 为伪随机函数）；渐进迁移 |
| 重要数据存储加密 | 按方案 | SM4（推荐 GCM 或 CBC+HMAC-SM3） |
| 数据完整性/签名 | 按方案 | SM3 HMAC / SM2 签名 |
| 传输加密 | 按方案 | 在网关终结国密 TLS（TLCP），应用一般不改 |
| 文件指纹、缓存键、ETag | 一般不需要 | 保留，并在工作项中写明理由 |

## 摘要

- Java：BouncyCastle `bcprov` 提供 `SM3Digest`，或通过 JCA `MessageDigest.getInstance("SM3", "BC")`。
- .NET：`BouncyCastle.Cryptography` 包的 `SM3Digest`。
- 前端：`sm-crypto` 等 JS 库（确认来源与维护状态）。
- **存量口令渐进迁移**：增加“算法版本”字段；登录时用旧算法校验成功后立即用新算法重算并更新；设置截止期后强制重置未迁移账号。不能把旧哈希直接“转换”成新哈希。

## 对称加密

- SM4 分组 128 位、密钥 128 位。Java `Cipher.getInstance("SM4/GCM/NoPadding", "BC")` 等；.NET 用 BouncyCastle 的 `SM4Engine` + 模式类。
- 存量密文：设计“解密旧 → 加密新”的批量迁移任务 + 双读期（读时识别密文版本）；密钥管理纳入密码机/KMS 方案。
- 不要自己实现分组模式与填充；不要用 ECB。

## 非对称

- SM2 用于签名验签与密钥交换。注意 SM2 签名需要用户标识（默认 `1234567812345678`），与对端约定一致，否则验签失败。
- 涉及外部系统（统一身份认证、支付、电子签章、CA）的，必须与对端约定切换方式与过渡期（双算法并行）。
- 证书：国密双证书体系（签名证书 + 加密证书），由 CA 签发。

## 传输层

- 浏览器到服务端的国密 HTTPS 需要支持国密的浏览器或客户端；通常在负载均衡/网关处使用支持 TLCP 的组件（铜锁 Tongsuo、GmSSL 构建的 Nginx、商用国密网关）。
- 服务间调用如需国密，评估 Tongsuo/BouncyCastle JSSE 国密套件【核对】。

## 测试要点

- 用国家标准给出的 SM3/SM4 标准测试向量做单元测试（例如 SM3("abc") 的标准结果）。
- 前后端互通测试：同一明文在前端加密、后端解密，反之亦然。
- 存量数据迁移测试：迁移前后业务读取结果一致。
