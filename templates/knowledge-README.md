# 项目知识库

由 tmh 和智能体共同维护，和代码一起提交。新同事和每个智能体会话都从这里了解项目，而不是通读代码。

| 位置 | 内容 | 谁写 |
|---|---|---|
| `index.md` | 系统总览 | 智能体撰写，人确认 |
| `domains/<id>.md` | 业务域 | 同上 |
| `flows/<id>.md` | 业务流（一个接口/定时任务/消息背后的业务） | 同上 |
| `entities/<表>.md` | 业务对象（表的业务含义、字段、生命周期、读写方） | 同上 |
| `modules/<名>.md` | 代码模块（职责、依赖、代码健康） | 同上 |
| `glossary.md` | 业务词 ↔ 代码 ↔ 表 | 智能体与人共同维护 |
| `decisions.md` `pitfalls.md` `open-questions.md` | 决定、坑、待确认问题 | 同上 |
| `domains.json` | 业务域名称与“业务流 → 域”的划分，可手工调整 | 工具生成，人可改 |
| `.pages.json` | 页面登记：状态、摘要、所描述代码的指纹 | 工具维护，勿手改 |

每个页面：
- 文件头：`title`（业务名）、`summary`（一句话）、`status`（未分析 / 待确认 / 已确认 / 过期）。
- `<!-- tmh:facts -->` 标记之间：工具从知识图谱生成的事实，带 文件:行号，每次 `tmh kb build` 自动刷新，**不要手改**。
- 标记下面：业务理解。结论标注证据 `文件:行号`，推断标【推断】，要问业务方的标【待确认】。

状态怎么变：
- 智能体写完并通过 `tmh kb done` 校验 → **待确认**
- 人看过 → `tmh kb confirm <id> --who <姓名>` → **已确认**
- 页面描述的代码变了 → `tmh kb build` 自动标 **过期**，`tmh kb next` 会把它排进修订队列
- 业务方答复了 `open-questions.md` 里的问题 → `tmh kb answer <编号> "<原话>" --who <答复人>`：原话写进问题行和相关页面末尾的“业务方答复”，页面排进修订队列；智能体修订后回到 **待确认**，再由人确认

读这份知识库：按原文读（`tmh kb chain "<需求>"`、`tmh kb read <id>`），引用页面 id，不另做摘要或副本。业务方的需求先 `tmh kb triage "<需求>"` 预判。

常用：`tmh kb status` 看覆盖情况；`tmh context "<需求>"` 按需求取相关知识；`tmh report` 生成可浏览的报告。
