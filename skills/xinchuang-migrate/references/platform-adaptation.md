## 精确环境与证据

| 维度 | 应记录的内容 | 必要检查 |
| --- | --- | --- |
| CPU | 厂商、型号、ISA、位数、端序、指令扩展 | 实机探测与二进制目标是否一致 |
| OS | 产品、桌面/服务器 edition、完整版本、SP、内核、libc | 厂商支持范围与真实安装环境是否一致 |
| 运行时 | 发行版、版本、构建、架构、配置 | 原生组件、垃圾回收器、TLS 和字符集 |
| 应用服务器 | edition、补丁、EE/Servlet 级别 | 部署格式、类加载、JNDI、事务与会话 |
| 数据库 | edition、完整版本、兼容模式、字符集、排序规则 | 建库参数、对象语义、驱动组合 |
| 驱动/SDK | 坐标、版本、哈希、原生库架构 | 支持矩阵、加载过程、异常及事务行为 |

从文档结论到工程完成至少经过：版本核对、静态分析、构建验证、业务测试、真实目标验证。每项记录适用元组和证据时间；环境变化后重审受影响结论。
未知为 `unknown`；未执行为 `not-run`；不可用依赖造成的阻塞为 `blocked`。不适用须写具体理由。

## 操作系统架构与本地组件

### CPU 与 ABI

- 不从品牌推断 ISA：麒麟官方下载区分别列出龙芯的 LoongArch64 与 MIPS64el 产品；同时区分 x86 与 ARM64 产品。[1]
- 核对 `uname -m`、发行版标识、内核与 libc；这些信息来自已授权目标环境，不从开发机结果推断服务器。
- 检查 ELF/PE 格式、动态加载器、库搜索路径、glibc/GLIBCXX 符号版本、位数及端序。
- x86_64、aarch64、LoongArch 构件不能互换；镜像清单与镜像内部全部原生二进制都要核对。
- 编译器、汇编、SIMD、原子指令、对齐和内存顺序问题通过目标架构测试定位。
- 交叉编译能验证构建链；仿真能辅助调试；两者都不应冒充实机验收。

### UOS、麒麟及 Linux 差异

- 固定产品、edition 和维护版本；桌面版与服务器版、不同 SP 或内核组合分别判断。
- 检查包管理、服务管理、文件权限、大小写、路径、临时文件、locale、时区与系统限制。
- 验证安全策略、端口、证书库和服务账户；适配问题不能通过长期关闭安全机制解决。
- 检查存储挂载、文件锁、进程信号、定时任务、日志轮转、备份代理和监控探针。

### Windows 与桌面依赖

| 依赖 | 要查的具体行为 | 可验证的处理方向 |
| --- | --- | --- |
| COM/ActiveX/Office 自动化 | 注册表、位数、交互桌面、插件生命周期 | 保留受支持服务边界或替换组件，并验证文件与业务契约 |
| 字体/打印 | 字体授权、缺字、度量、分页、驱动、双面与纸张 | 固定字体与渲染版本，抽查视觉结果与实体输出 |
| 报表/PDF | 模板引擎、图表、导出、签章、编码 | 对代表样本比较内容、布局和签章结果 |
| OCR/图像 SDK | 本地库、CPU 指令、模型、授权锁 | 核对目标构件与许可证，评测准确率、吞吐与资源 |
| 外设/密码设备 | 驱动、接口、固件、服务账户 | 使用实际型号与版本验证连接、故障和恢复 |

闭源组件没有目标构件时标记阻塞；不能将替代品视为无损替换，也不默认用户授权远程调用或上传数据。

## 运行时与应用服务器

- 国产化可以保留 Java、C/C++、Python、Node、Go、.NET 等既有技术栈；先判断实际支持范围。
- Java 记录发行版、完整版本与构建、架构、编译目标、JVM 参数、信任库及依赖原生部分。
- 检查 JDBC、JNI/JNA、密码提供者、附加代理、监控探针与垃圾回收器在目标构建上的行为。
- Java EE 与 Jakarta EE 代际影响部署描述符、Servlet/JPA/JMS 等 API 及第三方依赖。
- Tomcat 的 9→10 迁移说明指出 Java EE 8 到 Jakarta EE 9 的相关 API 包名变化。[6]
- 不全局替换 `javax`：`javax.sql`、`javax.crypto` 等 Java SE API 不机械替换；逐一核对组件使用的规范。
- 转换工具只能减少重复劳动；重新验证类加载、反射、序列化、事务、认证、会话与第三方扩展。
- 不因“Tomcat 兼容”推断某国产应用服务器支持全部规范；绑定实际产品 edition、补丁和支持矩阵。

## 数据库迁移语义

### 先确认模式与版本

达梦文档明确以“部分兼容”描述多种数据库模式；设置模式不等于完整复现源库行为。[2]
人大金仓的迁移工具与模式选择必须结合对应版本文档；同名模式不能替代对象与业务验证。[3]
OceanBase 文档所述租户兼容模式在创建时指定且之后不能修改；edition、版本及模式能力应逐项确认。[4]
openGauss 的迁移案例区分兼容、部分兼容与不兼容对象，并区分全量、增量与校验阶段。[5]

### 按业务契约核对

| 范围 | 必须验证的差异 |
| --- | --- |
| 标识符与命名 | 大小写折叠、引用标识符、保留字、schema/search path |
| 类型 | 数值精度、溢出、布尔、日期、时区、LOB/JSON、二进制与无符号数 |
| 空值与字符串 | 空串/NULL、尾随空格、字符长度、字节长度、排序与大小写比较 |
| SQL | 分页、连接、聚合、函数、MERGE/UPSERT、执行计划和参数绑定 |
| 生成值 | identity/sequence、自增、RETURNING、批量写入生成键、序列追平 |
| 事务 | 隔离级别、锁、死锁重试、自动提交、DDL 提交、分布式事务 |
| 数据库代码 | 存储过程、包、触发器、函数、异常、游标、动态 SQL、定时作业 |
| 安全与运维 | 用户/角色/权限、对象所有者、审计、备份恢复、连接池和故障转移 |
| 驱动/ORM | 驱动版本、方言、迁移工具、元数据、LOB/日期绑定与错误分类 |

在目标环境验证 schema、索引、约束、视图、程序对象、角色授权及运维任务，不只导入表和记录。
比较关键聚合、分区哈希、逐行抽样及业务不变量；容差须来自业务约定，不为消除差异临时放宽。
性能以代表性查询和并发负载为准；不同执行计划本身不等于错误，但需检验性能与锁影响。

### 有写入时的数据一致性

源系统持续写入时，离线抽样或两次独立导出的差异无法直接证明迁移失败或成功。
固定一致性快照和增量起点，验证 CDC 顺序、重复、删除、DDL、断点恢复和追平监控。
全量完成后仍需确认增量追平与最终水位；记录切换冻结时刻、事务边界和最终核对结果。
openGauss 案例说明部分全量校验场景要求没有持续增量写入；应先核对校验工具适用条件。[5]

## 离线交付与验收

- 收集构建插件、传递依赖、包管理缓存、运行时、驱动、镜像、字体、系统库和授权文件。
- 固定来源、版本、哈希、许可证及可再分发条件；依赖清单/SBOM 与实际交付物对应。
- 不把只含应用 JAR、一个容器标签或联网安装脚本的包称为完整离线包。
- 使用真实目标架构与受控无外网环境演练安装、升级、启动、核心业务、备份与恢复。
- 许可证激活、时间同步、DNS、内部镜像、证书更新和设备连接须有明确可用方案。
- 构建、安装、启动、业务等价、性能和恢复分别记录，避免一项通过掩盖另一项未执行。
- 无真实目标环境时交付改造与预验证成果，核心验收 `not-run`，切换仍阻塞。

## 带写入的切换与回滚

先定义单写端、冻结窗口、CDC 位点、健康门禁、RPO/RTO 和失败触发条件。
目标库开始接受写入后，旧库会落后；应用回退或路由回切不能恢复这些新增数据。
选定并演练反向同步、导出重放、保留兼容写入或明确的业务恢复方案，覆盖删除、冲突、重复与 schema 变化。
恢复演练必须证明备份可读、对象与权限可恢复、关键业务可运行，并测量真实耗时。
支付、通知、文件、搜索索引、缓存和外部系统等副作用另列重放/补偿规则，不能依赖数据库恢复自动解决。
如果没有已验证的数据回退路径，则阻止要求可回滚的切换；保留继续正向修复方案，并按已约定风险门禁决策。

## 危险默认值

| 错误假设 | 正确处理 |
| --- | --- |
| 国产化意味着全改 Java | 分别确定语言迁移与环境适配范围 |
| 同一 CPU 品牌等于同一架构 | 核对型号、ISA、ABI 与实际构件 |
| 兼容模式等于百分百兼容 | 精确版本验证 SQL、数据和事务语义 |
| 改连接串就完成数据库迁移 | 覆盖对象、驱动、权限、运维和增量写入 |
| 容器或仿真通过等于实机通过 | 在约定目标元组实测并保留证据 |
| 能启动等于业务可用或已获认证 | 分别记录业务验收与官方认证材料 |
| 全部 javax 都要替换 | 依据实际 EE 规范与组件边界修改 |
| 关 TLS/给管理员权限能算适配 | 保留安全要求，定位证书与最小权限问题 |
| 切回旧库等于回滚完成 | 验证目标新增写入和外部副作用的恢复 |
| “未测试”可以按低风险通过 | 保留 not-run，阻断依赖该项的切换 |
