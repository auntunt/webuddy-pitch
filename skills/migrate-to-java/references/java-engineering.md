## 目标环境与结构

先记录源语言、运行时、框架、序列化库、数据库、操作系统与部署方式的真实版本。
目标矩阵至少包含 JDK 发行版/版本/支持周期、OS/CPU、构建工具、框架、容器、JDBC、原生 SDK。
以目标平台支持范围与组织既有约束选版本；不要因为“较新”直接升级所有组件。
记录每个关键兼容判断的官方文档、版本范围和实测结果；文档支持与实测通过是两类证据。
如果使用 Spring Boot，查对应版本的系统要求，核实应用服务器及 Servlet 版本；其他框架同理。
固定 Maven/Gradle 包装器、Java 工具链和依赖版本；确认离线或内网构建实际需要的制品。
区分开发 JDK、编译字节码目标和运行 JDK；只设置 `source`/`target` 不能保证所有 API 可在旧运行时使用。
只按目标 Java EE/Jakarta EE API 与依赖代际处理 `javax`/`jakarta` 迁移，不全局替换 `javax.*`；`javax.sql`、`javax.crypto` 等属于 Java SE API。
原项目是模块化单体时可保留这一边界；迁移本身不要求引入微服务、消息队列或 ORM。

## 源语言语义

| 来源/场景 | 必须核实的差异 | 可执行的验证 |
| --- | --- | --- |
| Python `int` | 任意精度与 Java 固定宽度整数不同；按业务范围选择 `long` 或 `BigInteger` | 最大值、越界值、累加/乘法与序列化回读 |
| Python `//`、`%` | 负数取整规则与 Java 整数截断规则存在差异 | 正负被除数/除数及零；需要时显式实现源语义 |
| Python 动态类型 | `None`、缺失、空容器、真假判断与 Java 类型约束不同 | 缺字段、显式空值、空串、零、空列表 |
| Node.js/TypeScript 数值 | JavaScript `Number`、`BigInt` 与 Java 数值类型不可仅按名称映射；JSON 有精度边界 | 大整数 ID、指数形式、非有限数和客户端回读 |
| Node.js/TypeScript 对象 | `undefined`、属性缺失与 `null` 的输出不同；事件循环代码迁为并行代码可出现竞争 | 缺字段/空值 JSON、共享状态和有序事件 |
| TypeScript 类型 | 静态声明不等于输入在运行时已验证 | 非法实际请求、联合类型分支和宽松反序列化 |
| .NET `decimal` | 与 `BigDecimal` 的精度、范围、舍入和溢出行为不同 | 边界金额、多步计算、除法、币种精度 |
| .NET Task/LINQ/EF | 异步取消、延迟枚举、查询执行与跟踪语义不应机械映射 | 取消时机、重复枚举、查询数、事务结果 |
| .NET 平台依赖 | COM、P/Invoke、WMI、注册表、桌面 UI 和供应商驱动可能依赖 Windows | 列出 ABI/OS 依赖，验证服务化、替代实现或保留边界 |
| 所有语言的集合 | 相等、哈希、排序、迭代顺序、重复项与并发安全可能不同 | 相等键、重复值、大小写、排序与并发修改 |

不要为所有数字统一使用一个 Java 类型。业务 ID、计数、金额和测量值分别确定契约。
`BigDecimal` 的数值比较和对象相等不同：`compareTo` 可忽略数值等价的小数位差异，`equals` 还比较 scale。
从十进制字符串或明确的最小货币单位建立金额；不要把未经约定的二进制浮点直接变成金额基准。
除法显式约定 scale、`MathContext` 和舍入规则；无法精确表示的无舍入除法可能抛出异常。
源系统要求溢出失败时，不能依赖 Java 普通整数运算的回绕行为；选择检查运算或范围校验。
日期先判定是时间点、带偏移日期、地方时间还是纯日期，再选择 `Instant`、`OffsetDateTime`、`LocalDateTime`、`LocalDate`。
验证夏令时重叠/跳跃、时区数据库差异、毫秒/微秒精度和数据库往返；不能全局使用服务器默认时区。

## 接口与数据契约

从真实序列化配置和请求/响应样例提取契约，不从语言或框架默认行为推断整个系统。
特别区分 .NET 库默认配置与 ASP.NET Web 配置，以及 Newtonsoft.Json 与 System.Text.Json 的行为。

| 契约项 | 检查内容 |
| --- | --- |
| JSON 字段 | 名称/大小写、缺失/空值、默认值、未知字段、枚举名称/数值 |
| JSON 数值 | 大整数和金额是否用字符串、位数、指数格式、负零及非法数值 |
| 日期与标识 | UTC/偏移格式、精度、UUID/GUID 字符串/字节布局 |
| HTTP | 方法、路由、参数绑定、状态码、错误体、头、缓存、分页和顺序 |
| 认证授权 | 身份来源、权限检查点、租户隔离、拒绝结果和上下文传播 |
| 文件/文本 | 字符集、换行、BOM、Unicode 规范化、路径大小写与权限 |
| 数据库存储 | 空值、默认值、精度、字符排序、时区、生成键与约束 |
| 消息/外部调用 | 格式、键、顺序、重复投递、重试与幂等、副作用时机 |

对输出顺序或格式的规范化必须有契约依据；不要通过忽略字段、容差放宽或排序掩盖回归。
JDK 默认字符集跨版本可能变化；文件、网络和数据库边界应显式约定字符集。
浏览器 JS/TS 的 DOM、交互和渲染留在明确的前端边界；仅在用户要求时另行设计前端替代。

## 事务与异步

先画出一次业务操作的数据库写入、外部调用、消息发送、提交和失败恢复顺序。
核实源系统的隔离级别、锁、超时、嵌套事务、自动提交与重试范围，保持实际业务约束。
如果使用 Spring 声明式事务，默认回滚规则通常针对 `RuntimeException`/`Error`；checked exception 需要明确配置。
基于代理的事务通常不会拦截同一对象内部的自调用；从真实调用路径验证事务确实生效。
命令式事务通常绑定线程；新线程或异步任务不会自动继承原线程事务。
响应式事务依赖相应事务管理器与订阅上下文，不可将命令式和响应式调用随意混用。
比较 ORM 的延迟加载、脏检查、批量写入、生成键、刷新时机和查询数；防止 N+1 与提交时机变化。
对重复消息和超时重试验证幂等；确有跨资源一致性问题时再设计 outbox 等方案，不把它作为默认架构。

对异步实现明确以下事项：

- 每个任务的启动时机、依赖关系、顺序、最大并发和队列容量。
- 截止时间从何时计时、如何传播；超时后底层操作是否真的停止。
- 取消、异常聚合、部分成功、重试和资源释放的语义。
- trace、认证、租户与日志上下文如何跨线程或异步边界传播。
- 数据库连接、HTTP 连接、线程/任务数量和内存的共同预算。

虚拟线程适合大量等待型任务，不应被当作 CPU 计算加速器或取消所有并发限制的理由。
是否采用虚拟线程取决于所选 JDK、库及实际负载；相关限制按目标 JDK 文档和实测判断。

## 验证与性能

先运行源实现基线，保留源版本、测试数据、环境、已知失败和副作用快照。
差分验证使用同一输入和隔离状态，比较业务输出、错误与副作用；原实现不是唯一正确性的证明。
对旧缺陷单独建账；没有批准的行为变更不要混入“等价迁移”结论。
优先覆盖核心业务闭环、权限、金额、边界日期、并发、重复请求、失败恢复和回退。
仅在真正降低剩余风险时补充测试；覆盖率是线索，不是固定完成门槛。
运行项目已有静态检查和必要的构建/集成门槛；缺环境时记录未验证范围。

JVM 性能至少区分两组观测：

| 观测 | 记录内容 |
| --- | --- |
| 冷启动 | 新进程启动、类加载/初始化、就绪时刻、首个请求、启动内存 |
| 稳定负载 | 预热方案与稳定依据、测量轮次、并发、吞吐、延迟分位数、错误率、CPU、进程内存、GC |

使用相同或充分说明差异的硬件、资源限额、数据、依赖服务和负载，记录 JDK/GC/堆/构建参数。
保留原始测量及波动，不用单次最佳值宣传收益；预热时长不写成适用于所有项目的常数。
微基准采用适合 JVM 的测量方法，可参考 JMH，但业务性能结论必须有端到端证据。
先用实际 profile 找瓶颈，再考虑算法、SQL、连接池、分配或缓存；不强制 PGO/AOT/原生镜像。

## 交付与阻塞处理

为每个结论保存版本、环境、命令和证据路径。`pass` 只表示该项实际验证通过。
将缺失环境标为 `blocked`，尚未执行标为 `not-run`，不适用项写明理由。
对同一失败最多 5 次实质性修复或 15 分钟；预算耗尽后记录根因假设和所需条件，推进其他独立任务。
持续维护当前阶段、已完成批次、下一批、阻塞项和证据索引，恢复时从清单继续。
交付可复现构建、配置说明、源到目标映射、数据切换/回退方案和实测报告。
代码回退不能自动撤销数据库结构与已写数据；分别说明兼容窗口、备份恢复和需要人工处理的情况。

## 官方参考

以下链接用于核对语义和约束，不代表推荐所示文档版本作为迁移目标。使用时读取目标版本对应文档。

1. [Java `BigDecimal` API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/math/BigDecimal.html)：精度、scale、相等比较和除法规则。
2. [Spring 声明式事务注解](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html) 与 [`Transactional` API](https://docs.spring.io/spring-framework/docs/6.1.12/javadoc-api/org/springframework/transaction/annotation/Transactional.html)：代理调用、回滚及线程边界。
3. [Java 虚拟线程](https://docs.oracle.com/en/java/javase/21/core/virtual-threads.html)：适用负载、资源与并发注意事项。
4. [Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)：核对目标版本的 Java、构建工具和 Servlet 容器范围。
5. [Python 内置类型](https://docs.python.org/3/library/stdtypes.html)：整数精度、真值、数值运算及容器语义。
6. [System.Text.Json 属性配置](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/customize-properties) 与 [Newtonsoft.Json 迁移对照](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/migrate-from-newtonsoft)：序列化默认值和配置差异。
7. [JDK 18 发布说明](https://www.oracle.com/java/technologies/javase/18-relnote-issues.html)：默认 UTF-8 字符集变更及兼容事项。
8. [OpenJDK JMH](https://openjdk.org/projects/code-tools/jmh/)：JVM 微基准工具；不替代真实业务测试。
