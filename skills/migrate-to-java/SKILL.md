# 迁移到 Java

独立改编的专业指引，来源与修改见 NOTICE。它不授予执行权限，不改变项目模型路由或验收门禁。

## 接入现有计划

1. 先读取当前项目与工作目录、固定源提交、计划修订、已派发任务和操作回执。网页与个人MCP使用同一个改造计划，不创建第二份migration-log台账。恢复时先核对原运行；未知回执不能重发。
2. 通过既有需求确认保存业务契约。原始实现行为、客户确认的正确规则、获准修复的旧缺陷分别记录。AI说明和现场转述不是确认事件。
3. 使用[迁移蓝图](assets/migration-blueprint.md)补齐材料，关联到计划scenario.sources并记录文档版本；不要将模板内容标为已确认。固定提交写source_version、实际目标环境写target_environment；验收条款写criteria，前置条件写dependencies，引用代码范围用map_refs。
4. 按完整业务场景安排验收：输入→权限→规则→数据/消息副作用→输出与失败。业务域是实现范围，不是完整验收的替代。涉及多个域时保留各部分工单，父级固定集成候选验证整条链路；不越过当前任务范围擅改其他部分。
5. 在蓝图保存“场景/验收项→源路径与符号→目标路径与符号→用例ID→证据”的映射。把基线与候选、数据集及环境版本绑定；代码或标准变化后由现有证据规则复核，不沿用旧通过。

## 选择与实施

- 读取[Java工程检查](references/java-engineering.md)，按目标环境选JDK、框架、构建和部署格式；不默认最新JDK、Spring Boot、微服务或响应式架构。
- 明确后端、前端、桌面与外部SDK边界。Java后端迁移不等于改写浏览器前端；COM、Office、原生SDK需独立验证。
- 先形成可运行工程骨架，再选择最小完整业务链路。保留旧系统只读对照；在获准目标目录实施，不逐行翻译。
- 重点验证数值溢出/金额舍入、null与默认值、序列化与时区、异步取消/重试/幂等、事务/回滚/线程上下文、连接池与资源退出。
- 同时要求信创时，先读取xinchuang-assess/xinchuang-migrate并固定目标元组，再选Java技术栈；语言与平台两组结果分别记录，最终验证真实组合。

## 验证与交付

- 同一组固定输入比较旧/新返回值、错误、权限、持久化结果和消息；仅规范化契约明确允许的差异，保留原始输出。旧系统输出不是正确业务规则的唯一来源。
- 构建与测试用现有项目测试配置和受监管执行器执行，默认位置或项目明确覆盖决定执行机器；不通过本技能直接启动未登记的远程执行。
- 用现有逐项证据关联验收条款，至少准备一个违反独立业务预期的错误候选，确认检查失败且不能放行。
- 性能区分冷启动与预热，记录负载、硬件、JVM配置和波动；没有同条件基线不计算提效百分比。
- 环境、数据、权限和业务规则缺失进入blocked/not-run；代码问题遵守平台当前次数、时间和用量预算，不另设无限循环或固定覆盖门槛。
- 使用[验收模板](assets/acceptance.md)补齐可阅读材料，最终结论来自平台保存的运行回执、独立检查和真实人工事件。不得手填pass替代执行、代人验收或自动生产切换。
- 计划已派发后，新增规则走现有后继草稿/修订入口。原计划、正在运行任务及历史证据保留；文件与Git检查点不证明进程已停止。
