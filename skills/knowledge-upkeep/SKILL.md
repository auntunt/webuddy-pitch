# 知识库增量维护

知识过期比没有知识更危险：后续会话会相信错误的说明。知识库的每一页都记录了它所描述代码的指纹，代码一变，工具就能精确指出哪些页面要改，**只改这些页面，不需要重新分析整个项目**。

## 步骤

1. `tmh kb build`：增量重建图谱（只重新解析改过的文件），输出“代码变化导致 N 个知识页过期”。
2. 循环 `tmh kb next` → 修订页面 → `tmh kb done <id>`，直到没有过期页面。
   - 过期页面的上下文包里有**旧的说明**和**变化的代码节点**，只改受影响的段落，其余保留。
   - 行为变了：改写结论，注明“自 <任务ID/提交> 起”。无法确认：标【待确认】。
   - 修订后状态回到“待确认”，等人重新确认。
3. 本次任务产生的新知识补进对应页面：
   - 新增入口/表 → `tmh kb build` 后会出现在任务队列里，照常撰写。
   - 新的术语、决定、坑 → `glossary.md`、`decisions.md`、`pitfalls.md`。
4. 改造任务同步工作项台账（`tmh items --set ...`）。
5. `tmh report` 重新生成报告。

只写能帮助下一个维护者的内容，不写流水账。
