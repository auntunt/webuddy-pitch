## 紧凑设计决策单

| 决策 | Webuddy 的处理 |
| --- | --- |
| Surface | 产品工具，主要是 command-led 工作台。使用者推进真实软件交付、判断阻塞、检查产物并采取下一步；详情兼有阅读与审查。 |
| P1 | 当前项目范围、待推进交付和真实状态。 |
| P2 | 当前阶段、需要关注的阻塞、可执行下一步。 |
| P3 | 具体产物、运行、版本、验证和历史记录；按需要展开。 |
| Action | 在列表创建或继续交付；在详情保存产物、开始运行、查看证据或记录人工复核。每个行动区域有一个明确主操作。 |
| Content truth | 数字与状态来自现有 API；没有数据时给空态和创建入口。保留原始目标全文、错误、代码版本及完整产物；不制造成功率、客户、运行数据或发布宣称。 |
| System | 全站共用浅色中性工作面、深色正文和受控强调色。语义色用于失败、待处理、运行等状态，并配文字。CJK 兼容系统字体；固定字号层级；正文约 14–16px；等宽仅用于真实代码和标识。 |
| Spacing/material | 4px 基础尺度；普通内容用间距和细分隔线，边框只界定可操作对象和表单。统一控件、圆角、焦点和层级；不把每个段落变成卡片。 |
| Signature | 可追溯的交付进程：每个阶段能进入真实产物和运行。阶段路径是导航与状态，不是虚构的装饰进度条。 |
| Cliche budget | 不添加背景网格、霓虹、玻璃、巨幅口号、营销型指标卡或伪终端。真实工程图谱保留空间图形的业务用途。 |
| Main risks | 全局壳与旧工程页视觉脱节；窄屏导航和工作区彼此挤压。用跨路由、真实长内容、键盘和多视口浏览器证据检查。 |

宽屏区域关系：

```text
+---------------------------------------------------------------------+
| Webuddy / 工作区范围       项目选择        录入需求 / 助手 / 当前用户   |
+----------------------+----------------------------------------------+
| 全站导航             | 页面标题 / 当前范围                 主操作    |
| 交付 / 今日 / 客户    | 当前状态与筛选                               |
| 需求 / 版本 / 工程    | 可比较的真实记录 / 阶段产物 / 表格            |
|                      | 深入证据与历史             [按需助手]       |
+----------------------+----------------------------------------------+
```

移动端区域关系：

```text
+------------------------------+
| 工作区 / 项目 / 导航入口      |
+------------------------------+
| 当前任务标题 + 明确主操作     |
| 当前状态 / 可横向浏览的阶段   |
| 真实记录或表单               |
| 次级证据按需展开             |
+------------------------------+
| 可达的主要导航               |
+------------------------------+
```

该线框说明区域职责，不强制新增某种导航控件。实现须保留现有路由、数据行为、权限和入口。

## 采用原则与适用边界

| 来源原则 | 采用方法 | 不直接采用的建议及理由 |
| --- | --- | --- |
| Impeccable 区分 product 与 editorial | 固定字号、熟悉控件、可比较的信息密度、明确状态；优先 product reference。 | 根文件中展示字体、双字体、极端风格和视觉惊喜的泛化建议不适合反复操作的中文工作台。product reference 明确允许系统字体和单字体。 |
| Design Visual 的主角与区域职责 | 工作记录、当前状态、下一步先于品牌说明；宽屏留白必须服务阅读或比较。 | 不使用登录页/营销页的巨大视觉分栏；这里没有需要推广的产品照片或品牌故事。 |
| 一致的组件语法 | 全局按钮、表单、状态、链接、弹层、边框和 focus 使用共享规则。 | 不在每条路由复制独立黑白或深色主题；图谱可有受控的深色画布，不更改全站语义。 |
| 真正的交互状态 | 有名称的按钮、持久字段标签、loading/disabled、错误恢复、空态入口和可见焦点。 | 不用动画、彩色卡片或新增提示文案代替真实功能。 |
| 无损内容真实性 | 目标、日志与产物完整保存且可打开；代码采纳、测试、产物复核与正式发布分别陈述。 | 不因“版面简洁”截断数据、删除字段、裁剪证据或制造通过率。长内容通过换行/滚动/可展开视图呈现。 |
| 多视口视觉证据 | 使用现有浏览器工具、真实页面和原始截图，交互后复验。 | 不为审美检查安装新框架；不将图片降采样或重新编码，不把静态源码命中当作视觉验收。 |
| 动效服务状态 | 仅短暂交互反馈；reduce-motion 下停用非必要动画。 | 图谱辉光、持续脉冲、页面入场编舞不计作交付功能，不能压过状态阅读。 |

## 改造前跨页问题清单

以下为改造前源码检查所得，不宣称已经通过浏览器复现；实现后必须逐项核验。

| 位置 | 观察 → 原因 | 处理方向 | 复验 |
| --- | --- | --- | --- |
| `ui_css.py` / `ui_work.py` / `ui_delivery.py` | 工程页 navy 顶栏与嵌套 sheet、交付页独立黑白 scoped 样式并存 → 相同控件随路由变形。 | 全站 token 与 app shell 统一；页面只规定内容布局。 | 交付、今日、需求、版本、工单、运行、知识库、设置来回导航。 |
| `#top` / `#nav5` / `#tabs` | 顶栏聚集品牌、项目、服务、点数、需求录入、助手和用户；手机靠多项隐藏避让 → 上下文和入口容易丢失。 | 明确窄屏优先级和折叠规则；保留项目范围与关键导航可达性。 | 390、768、1440；长中文品牌、项目名、登录名。 |
| `modal()` / `.mx` | 通用 div 弹窗与 click-only 关闭按钮无 dialog 语义、焦点约束或返回 → 键盘可能操作背景。 | 统一弹层语义、命名、Escape、焦点进入/约束/恢复。 | 新建客户/项目、查看运行、关闭后回到触发入口。 |
| `.pts` / `.me` | div/span 只绑定 onclick → 键盘没有可操作语义。 | 原生 button/link 或等价键盘与角色。 | Tab、Enter、焦点可见。 |
| `.ain textarea` / 通用控件 | textarea outline 被清除；交付专用 focus 与旧工程页不同 → 焦点不稳定。 | 全局 focus-visible；包括按钮、链接、summary、输入和助手。 | Tab 循环；浅底、深色图谱、弹层均可见。 |
| 客户编辑 / 需求录入 | 多个字段只有 placeholder；输入后字段意图消失。 | 补持久 label 或程序化名称，错误与字段关联。 | 可访问树、输入后识别字段、错误后原文仍在。 |
| `.live` / `.atl` | 持续 pulse/流线动效；旧 reduce-motion 仅覆盖交付 route。 | 全站 reduce-motion；保留有业务意义的静态状态。 | 浏览器减少动态效果模拟或对应样式匹配。 |
| 版本页文案 | “验收通过”“现在的版本一直开着”等固定承诺 → 无法反映真实预览或验收状态。 | 用真实主干、预览、运行、复核状态陈述；区别可操作入口。 | 有预览/未运行/失败等实际响应。 |
| 交付页宽屏 | `.dl` 固定 1240px，详情 244px 侧栏与大间距 → 宽屏需检查闲置空间和正文尺度。 | 列表扩展比较区域；阅读正文限行宽但辅助证据有用途。 | 1920 和 2560 原始截图，不能用缩小截图代替。 |

## 浏览器与行为验证矩阵

| 范围 | 390×844 | 768×1024 | 1440×900 | 1920×1080 | 2560×1080 |

| 交付列表、创建入口与筛选 | 必测：顺序、按钮、无全页横溢 | 必测：断点过渡 | 必测：任务与操作层级 | 必测：比较区域 | 必测：全局壳和宽屏空间职责 |
| 交付详情、阶段与产物 | 必测：阶段可达、正文换行 | 必测：双栏切换 | 必测：主次区域 | 与列表同体系检查 | 与列表同体系检查 |
| 今日、客户、需求、版本、工程 | 代表页逐一导航和核心控件 | 至少一处中间宽度 | 跨页截图与操作 | 检查表格/图谱宽度 | 检查固定宽正文不孤立 |
| 运行详情与通用弹窗 | 不遮挡关闭/主操作 | 焦点和滚动 | 打开、切换tab、关闭 | 无需单独新截图 | 无需单独新截图 |

必须实际操作：导航与项目切换、打开/收起新建草稿、类型选择、草稿输入恢复、空态/错误、运行详情 tab、至少一个通用弹层、键盘焦点。任何会开启模型运行、采纳、合并、发布或客户签收的按钮，不因视觉验收而触发。

检查台账需记录原始截图路径、浏览器尺寸、实际内容来源、测试动作和结果。任何横溢、裁切、重叠、无标签、不可操作焦点、死按钮或状态误报都是修复项，不能与其他页面的通过项平均成“通过”。最终验证状态写入本轮验收记录；本调研文件不虚填通过数量。
