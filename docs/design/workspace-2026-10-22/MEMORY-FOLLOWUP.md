# 知识与记忆入口及验收沉淀修复

2026-10-22，复核「项目知识 / 长期记忆与共通方案 / 同类问题」的实际使用链路。

此前三个入口已有数据接口和操作，但记忆页保存了独立项目选择，未跟随顶部范围；页内切换分区没有更新地址，刷新会回到原分区。全局仅展示已共享方案，却没有直接进入项目已有经验的入口。新团队固定候选的业务验收也没有调用经验沉淀，旧验收流程正常不能代表新流程已接通。

本次调整：

- 统一页面与顶部项目范围；分区写入路由，刷新保留；全局页直接进入项目经验或同类问题；知识目录直接打开项目知识库。
- 固定候选的明确业务验收生成待确认记忆，保存原始需求、候选提交、评估、复核、合并、人工验收和使用过的记忆来源。成功办法和失败反例分别记录，不自动共享。
- 同一原始验收重复提交仅补写记忆，不新增验收或状态事件。记忆写入失败后，已关闭任务仍显示待补写状态和授权复核人的专用恢复按钮。使用结果按验收时快照归因，不将后续使用计入旧验收。
- 同一候选后续验收失败时，将其已经启用的成功经验暂停复核；原文和历史保留，不影响无关经验。
- 团队操作结果显示记忆状态，并直接进入该项目的记忆；跳转清空旧检索。异步反馈绑定原弹窗，避免写到后来打开的任务。

实现边界：知识目录整合已有知识页和经验；已验收的候选说明与文件清单先形成待整理记忆，不声称已自动推导根因。同类问题目前用同项目业务流、文件和异常特征产生建议，需人工判断。组织共享与引入仍是明确操作。

本机用合成项目实际打开页面，检查项目范围、分区切换及刷新、空知识目录入口；另用真实临时 Git 仓库和明确合成的检查证据，实际登录测试账号，完成关闭任务的记忆补写，再打开带固定提交来源的待确认记忆。未用客户数据进行验收、共享或模型任务。

新增回归覆盖范围/路由、全局入口、候选来源显示、补写状态，以及候选验收的成功/失败、幂等、写入恢复、撤销旧成功经验和使用归因。发布使用相关测试、隔离 HTTP 检查、完整备份和原数据读回；本次不改变数据库表结构。
