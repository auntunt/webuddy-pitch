# Webuddy UI/UX 方向探索 · 2026-10-22

本目录是方向研究，不是已上线页面。三份原型使用同一份虚构任务数据 `content.js`，没有客户材料、业务凭据或生产数据；只展示首屏视觉，尚未连接业务操作。

## 产品判断

这是供软件交付与维护团队连续工作的产品。首屏的主角是需要处理的事项：谁负责、为什么等待、依据是什么、下一步怎么做。维护、重构和知识沉淀共享项目事实与证据，但不能把模型运行完成、测试通过、人工验收混成一个状态。

调性：安静、精确、适中偏密、轻表面、庄重。原因是需要长时间阅读中文、跨项目切换并做有责任归属的判断。首屏不放营销口号，不用大数字成功率代替真实队列。

## 三个方向

### A · 接力工作台（推荐）

- 北极星：每次打开，都能知道当前需要谁做什么，并就地查看依据。
- 生成引擎：团队交接这一真实动作。把“待我处理”队列和当前任务的交接事实放在一起。
- 骨架：固定左导航，主区约 62% 是 6 条任务队列，约 38% 是选中任务详情。页头两行以内，第一条待办不被统计卡挤出首屏。
- 色彩：沿用现有产品的森林绿方向，`#F7F9F7` 画布、`#235D48` 主动作、`#DCE4DE` 分隔；选中底 `#DFEAE1`、白色内容面。
- 字体：中文系统无衬线；27px 页面标题、21px 当前任务、14px 任务名、12px 辅助元数据。编号按需等宽。
- 主视觉：任务之间的接力关系与当前证据；不额外放装饰图片。
- 控件：6px 圆角，1px 细边，动作常显；状态同时有文字。普通任务行不套多层卡片。
- 取舍：以执行者和项目负责人日常工作为重心；组织汇总成为项目/团队页。延续已有绿色资产，减少整站视觉迁移成本。

### B · 项目调度表

- 北极星：一次横向扫视多个项目的阻塞、负责人和下一步。
- 生成引擎：跨项目排期与交接表。以统一列位置替代大量摘要卡。
- 骨架：顶部主导航，通栏任务表，底部三个待决策摘要。没有常驻左栏，优先给任务、责任人和等待时间横向空间。
- 色彩：`#202E44` 墨蓝结构，`#F6F7F9` 画布，`#CA863A` 只标当前需要判断的行；选中底 `#FBF5E9`。
- 字体：Helvetica Neue + 中文系统无衬线；28px 标题，14px 表格正文，编号等宽。
- 主视觉：同列可比的项目状态；没有伪造进度图。
- 控件：3px 圆角、紧凑边框、文字动作。
- 取舍：调度效率强，但通栏表在窄屏更难，连续复核需另开详情。作为项目总览页的版式比整站默认更合适。

### C · 证据与交接

- 北极星：每次交接都像读一份有来源、有边界的工作记录。
- 生成引擎：版本化工作记录。对象目录、当前结论、来源边栏形成连续阅读。
- 骨架：顶部主导航，左侧待办目录，右侧任务主文；主文内部保留依据边栏。主角是一个完整对象而不是统计概览。
- 色彩：`#F8F7F3` 中性浅底，`#694575` 灰紫主动作，`#EEE8F1` 引用面；紫色对应来源和认知层，不与成功状态混用。
- 字体：中文系统无衬线正文；Georgia 只用于品牌字；30px 主任务标题、14px 阅读正文。
- 主视觉：结论、适用条件和来源之间的排版关系。
- 控件：5px 圆角、少量边框，阅读以分隔线为主。
- 取舍：适合复杂重构评审与知识维护；大量日常任务逐项处理效率低于 A。其阅读结构适合复用到 A 的知识详情页。

## 信息架构

| 一级入口 | 首要问题 | 次级内容与既有入口 |
|---|---|---|
| 工作台 | 现在有哪些事情需要我处理？ | 待我处理、等待外部、正在执行、最近进展；按责任与下一步分组 |
| 项目 | 这个系统处于什么状态？ | 项目概览、维护、重构、交付、版本、客户；架构、监控、依赖、外部系统、设置保留在项目上下文 |
| 任务 | 有哪些工作需要推进？ | 需求澄清、工单、重构子任务、知识确认；统一筛选与对象详情，保留不同验收条件 |
| 团队 | 工作停在谁手里，交接什么？ | 责任、复核、待决策、等待客户与交接；不做重复聊天产品 |
| 知识与记忆 | 我们知道什么，为什么可用？ | 知识页、资料与引用、项目事实、业务规则、决策经验、团队记忆；图谱作为知识的视图 |

全局页面默认显示团队范围；进入项目后，页头持续显示项目与版本上下文。切换项目不能使用户误以为旧任务、引用和人工确认已经适用于新项目。

## 知识与 automemory 的界面原则

1. 区分原始资料、代码事实、人工确认的业务认知、任务决策经验、跨项目团队规则，不全部叫“知识”。
2. 每条记忆显示来源、项目/版本、适用范围、确认人、更新时间和当前有效性。未确认推断与确认规则必须外观可区分。
3. 自动提取先形成候选记忆；接受、编辑、拒绝和失效都留下记录。自动记录不代表自动获得团队共享权限。
4. 任务详情直接显示“本次使用的知识”；知识详情反向显示“哪些任务采用过”。相同内容复用不继承来源项目的验收结论。
5. 固定引用更新仍由人明确选择版本；过期、授权撤销与不适用进入可处理队列，不仅在后台报错。
6. 查询默认当前项目；跨项目检索只包含明确授权并绑定的来源。全局知识首页不暗示已经存在完整组织级多租户隔离。

已有依据：`tmh/platform/ui.py` 的知识确认与待更新队列；`ui_library.py` 的固定引用、原文回读、差异对比；`docs/project-library.md` 的版本、授权与工作区边界。整体重组复用这些能力，不宣称它们缺失。
