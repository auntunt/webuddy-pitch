# I1：完整blocks的类型敏感比较

独立3b复审发现Python容器相等把嵌套true/1、false/0误判为相同。修复不删除扩展字段、不只比较text，不裁剪原始blocks或长正文。

固定评估器对双方完整**已解析JSON值**分别做规范序列化后比较：UTF-8/Unicode完整保留，对象键排序、数组顺序保留，null/string/bool/number保持各自表示。评估输出schema升级为oracle-exact-blocks-v2，父进程仅接纳该版本；原始候选字节摘要、角色UID和完整回执绑定继续保留。

数字合同明确采用Python标准JSON对已解析有限数值的规范表示：整数1与浮点1.0不同，-0.0与0.0不同；1e0与1.0在解析后同为1.0，因此相同。对象键的原始排列及数字源文本词法不构成比较依据；不声称恢复上游已经解析的浮点精度或比较原始数字词法。完整原native body仍按原字节保留。非有限数值不进入成功比较，产生原固定错误路径。

新增测试分开标注：完整WORKER的内存Path/UID投影只验证数据比较，不证明OS角色隔离；另外在root-owned临时Linux源树，用真实原provider回环、候选/独立评估UID验证深层true/1、false/0及同值长正文/扩展结构。原独立六场景逐字重放和原两红灯单独保存，不用新通过覆盖旧失败。

本修复不调整根预算、3秒角色时限、guard、权限、错误边界或人工确认，不接生产入口。真实任务、模型付费和组织收益仍未证明。
