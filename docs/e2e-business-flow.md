# 端到端运行：用 business-flow 技能梳理业务流

日期：2026-10-07  
引擎：Claude Code 2.1（`claude -p`，非交互）  
对象：`examples/legacy-java-oa`（Spring + MyBatis 请假审批，安装 tmh 后运行）  
耗时与花费：约 56 秒，19 轮，0.27 美元

## 指令

> 用 business-flow 技能梳理这个项目的业务流：挑核心流程补写业务说明（不要标已确认），记录分析过程，最后生成报告。用中文简短汇报。

## 智能体做了什么（来自 `.tmh/activity.jsonl`，钩子自动记录）

1. 加载 `business-flow` 技能，运行 `tmh map`、`tmh flows`：识别 6 条业务流、1 个状态机。
2. 逐条运行 `tmh flows <id>` 看提交、审批、驳回、超期作废的调用链；读 Service 和 Mapper XML 核对。
3. `tmh flows --notes` 生成说明模板，补写 5 条写表或定时的流程，全部保持“待确认”；列表查询只读，未补写。
4. 用 `tmh note` 记下 4 条发现、1 条取舍、4 个疑问。
5. `tmh report` 生成报告。

## 结果

- 5 份业务说明见 `docs/e2e-business-flow-notes/`；报告见 `docs/demo-report.html`。
- 智能体发现的问题（都能在代码里核实）：
  - 驳回不检查更新行数，对非待审批单据驳回不报错，仍写驳回日志；
  - 提交方法注释写“超过 3 天需部门经理审批”，代码只校验 1~30 天；
  - 所有接口没有权限校验，申请人和审批人来自请求参数；
  - 每晚导出任务依赖 `C:\` 和 `cmd copy`，Linux 上跑不了；
  - 超期作废不写审批日志。
- 没有把任何说明改成“已确认”，符合技能要求。

## 运行后修正的问题

- 单条 `tmh flows <id>` 在时间线里只显示“运行 tmh flows”，改为“查看业务流 X：名称”。
- 报告把未填写的说明模板也算作“已整理”，并显示模板占位文字；现在未填写的模板不进入报告。

## 局限

- 样例项目很小（4 个接口、2 个定时任务），不能代表真实项目上的耗时和质量。
- 这次用的是 Claude 模型；Codex + 国产模型下尚未运行。
