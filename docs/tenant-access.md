# 组织、成员与项目权限

登录后从顶部切换组织，或打开固定地址 `/t/<组织ID>/`。组织重命名不会改变地址。每次切换都会重新加载页面；草稿按实例、账号和组织分别保存，不能跨组织提交。

## 管理入口

平台所有者或组织管理员可从「成员与权限」进入管理页。平台所有者先创建个人账号，再创建组织并指定管理员；组织管理员添加已有账号、分配成员角色和项目权限。账号密码至少 8 位，仅以加盐 PBKDF2 摘要存储；管理审计不保存密码。

| 身份 | 能做什么 |
|---|---|
| 平台所有者 | 创建组织和账号、重置密码、启停账号、管理组织及授权；没有成员身份时只能管理，不能读取该组织业务 |
| 组织管理员 | 管理本组织成员与项目授权，读写本组织项目；不能管理全平台账号或开启宿主执行 |
| 普通成员 | 仅能访问明确授权的项目，按项目角色操作 |
| 只读成员 | 仅能读取明确授权的项目；即使项目授予更高角色也不能写 |
| 项目 manager | 管理项目协作配置、分配任务及可用知识引用；不获得组织管理权 |
| 项目 contributor | 登记、编辑需求和任务、评论、参与已授权交接；仍受指定负责人/复核人要求约束 |
| 项目 viewer | 读取项目、任务与记录，不能修改 |

成员身份不会自动授予项目访问权，组织管理员除外。任务分配不会授予项目权限。移除成员同时删除该成员在组织中的项目授权；停用账号会使所有组织的会话失效。不能移除最后一位有效组织管理员，也不能通过管理界面停用平台所有者或降低自己的管理权。

管理页显示实际修订号、操作人和审计记录。并发修改时需重新读取；一次请求的精确重试返回原回执，不重复执行。任何授权变化都会使已有页面的授权上下文失效，旧页面清屏并要求重新读取。密码重置或账号停用后必须重新登录。

## 人工确认保持独立

角色和权限只决定能否进入操作。知识采用、候选复核、验收、关单仍必须由对应个人账号通过原有证据和状态校验。平台所有者没有自动签字资格；Agent、自报显示名和旧共享令牌均不能替人确认。

## 本版明确限制

- 新组织使用独立数据目录、SQLite 和工作进程，但这些不是 OS 执行沙箱。新组织的模型、构建、脚本和预览执行保持关闭，没有启用开关。
- 默认组织保留原项目及路径，只有同时具有成员与项目权限的可信平台所有者可以使用旧宿主执行。普通成员、普通组织管理员的 Git 提交证据核对与依赖该核对的候选评审也暂受限；拒绝执行时不会把未知结果显示为通过。
- 所有受管组织，包括默认组织，暂不签发公开分享、签收、捕获回调或预览票据，也不启动预览服务。旧链接不可作为绕过租户登录的入口。
- 未完成项目过滤的全局统计、客户与知识目录仅供组织管理员使用。新路由未登记权限策略时默认拒绝。
- 自动恢复、自动流转、自动合并和常驻预览不会在受管工作进程启动时恢复。已启动的可信执行按原监督进程机制清理；撤权不代表取消按钮，也不代表业务操作已经回滚。
- 首版私有工作进程依赖 POSIX 和 Unix socket；Windows 未支持此网关。SSO、MFA、组织配额、外部邀请、独立执行环境和跨租户知识发布协议尚未实现。

## 原实例迁移

由服务器操作者在停止旧服务、完成完整备份后执行：

```sh
python3 -m tmh access-init --data /path/to/existing/data --owner existing-personal-account
```

必须明确指定已有有效个人账号。旧业务数据库、项目路径、用户文件及会话密钥保持原位；独立控制面位于 `control/access.db`。旧账号迁为默认组织普通成员，指定所有者成为默认组织管理员。重复执行同一个 bootstrap 不重复授权或新增审计。迁移后的会话格式和账号 epoch 会使旧登录失效，需要重新登录。

启用控制面后，不能恢复忽略权限的旧程序来“回滚”，否则会重新接受旧账号或旧凭据。发布异常应停止候选服务、保留全部当前数据，再部署能读取同一控制面的修复版本；不能用旧备份覆盖迁移后的业务写入。正式发布证据见 [进度记录](self-improvement/ralph-port-progress.md)。
