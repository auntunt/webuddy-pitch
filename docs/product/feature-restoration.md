# 完整流程入口恢复

新版默认首页改为团队任务总览，保留项目筛选、阶段、待接收、待复核、待分配、责任人、阻塞原因及分页。任务沿用服务端给出的下一步操作，可进入完整处理页面，也可进入新版开发记录。

新增原生 AI 助手：项目会话历史、对话、操作记录、继续/停止、归档/恢复。断线重试复用请求编号。助手仍受既有项目模型配置、成员权限和业务确认规则约束；未配置模型时显示实际错误。

“全部功能”提供 29 个可搜索入口，涵盖需求协作、改造交付、项目知识、效果管理。成熟功能继续使用原有页面和 API，不声称这些页面已经全部迁移至 Vue。

| 需要补齐的流程 | 本轮实现 |
| --- | --- |
| 从整体项目看任务，明确谁接下一步 | 新版任务总览、团队分工与复核入口 |
| 多项需求有依赖、批次和整体集成 | 恢复整体改造计划、改造任务、依赖关系入口 |
| 需求、会议、开发与交付能够接续 | 恢复需求收集、会议行动、客户沟通、交付与版本入口 |
| 项目经验能被找到并核对来源 | 保留原生经验记录，恢复交接说明、局部地图、知识评审和引用入口 |
| 评价功能、实际结果和使用效果 | 保留候选验证，恢复交付、提效和试点记录入口 |

本轮恢复入口和两个原生页面，未新建多智能体编排引擎，也未代人确认知识、验收或关单。聊天原文和个人信息不进入源码或公共文档。

验证：前端类型检查与构建、6 项定向组件检查、真实本地 Python 服务登录后的桌面/390px 页面与入口检查。助手协议使用模拟回执验证，未调用真实模型；Windows安装与测试站发布情况以对应版本回执为准。

## 任务目标与责任接续

新建任务可明确选择需求开发、缺陷、变更、运维数据问题或咨询排查。验收目标按条写入原任务正文，保留用户原文；保存不自动启动执行。任务详情显示负责人、复核人和后端给出的当前进展，并提供分配、复核、交接和验收入口。

增量验证：4项工作台组件检查、构建通过；隔离服务实际保存运维任务并读回类型、完整原文和两条验收目标，确认运行数为零；桌面/手机渲染检查通过。客户验收与真实效果数据仍由实际使用产生。
