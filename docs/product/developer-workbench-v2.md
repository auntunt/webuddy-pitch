# 开发工作台：第一轮

入口：`/next/`，选择项目后进入 `/next/p/<项目>/work`。

这轮复用现有工单、执行器、独立工作树、知识上下文与候选验证能力。新工作台集中呈现需求、执行记录、结果、完整代码差异、验证回执和日志。需求先保存；操作者随后选择分析、方案或开发。启动仍经过后端原有权限和执行条件检查，执行结束不等同于验证通过或业务验收。

方案先呈现行为变化、关键代码建议和依赖顺序，再展开详细依据。保留机器可读计划与原有验收标准。代码差异来自实际运行记录，不从模型叙述推造。旧版知识库、设置和全部工单入口继续可用。

参考 [HelixHarness](https://github.com/didi/helixharness) 的 Propose → Apply → Archive、按需加载项目知识及按依赖推进任务的设计。这轮没有复制第三方源码、安装它的插件，或引入它的全套评审流程。现有知识与执行后端继续是状态来源。

## 本轮边界

- 已实现：需求保存、按项目切换、按需启动既有执行模式、轮询运行、查看完整产物、进入候选验证、修复重复 hash 导航。
- 已验证：前端构建、需求真实接口写入、桌面和窄屏渲染、原始运行产物展示与跳转；定向用例覆盖保存不自动执行、运行读取竞态和链接。
- 未验证：客户 Windows、真实模型完成整轮开发、客户仓库的启动/测试。
- 后续：多需求依赖编排、开发环境自动准备、杂乱仓库识别与拆分。不能把本轮界面接通称为这些能力已经完成。

保留现有人工确认与验收规则。本轮没有增加全量测试或恢复长期自动审计。
