# Webuddy 独立产品版本

Vue 前端位于 `web/`，通过既有 Python HTTP API 读写业务状态。构建产物由服务提供 `/next/` 入口，前后端可以分别开发；客户端不直接访问数据库。

## 使用流程

1. 在项目首页接入本机目录、导入 Git 仓库，或创建网页项目。
2. 在项目设置中选择执行器、填写开发环境启动命令和相关检查命令。
3. 在工作台保存需求，再选择分析、方案或开发。多个相关需求可先拆分、澄清，再指定依赖和每批任务数。
4. 查看实际运行结果、完整代码差异、检查回执和日志。可补充要求、停止、重试或继续处理。
5. 采用改动后启动对应版本的预览；业务确认仍使用原有验证入口和权限规则。

知识库和常用设置已接入新界面。高级连接与访问配置保留旧版入口。方案优先说明行为变化、关键实现和依赖顺序；运行结束不等于验证通过或业务验收。

参考 [HelixHarness](https://github.com/didi/helixharness) 的 Propose → Apply → Archive 和按依赖推进任务的设计，复用本项目的工单、独立工作树、知识上下文和候选验证能力。

## Windows 安装

使用 `Webuddy-Setup-<版本>-x64.exe`，支持 Windows x64。双击安装，按向导完成后打开桌面 Webuddy 图标。Python、Node、Git 和已有支持的执行器运行依赖随包提供；无需使用者手动构建或运行 PowerShell 命令。

- 默认安装到当前用户的程序目录，无需管理员权限。
- 数据和配置保存在 `%LOCALAPPDATA%\Webuddy`，升级和卸载保留。
- 默认提供 Cursor CLI 安装选项：优先复用已有安装，否则联网运行 Cursor 官方安装程序。模型账号不随包分发。
- 首次需要认证时，使用开始菜单的“登录 Cursor”；已有可用登录由 Cursor 自行复用。
- 仅本机使用时无需配置防火墙。勾选局域网访问后，由向导发起管理员权限请求，允许本地子网访问。
- 开始菜单提供启动、退出、环境检查和卸载入口。升级前如仍有任务运行，先在工作台停止或等待完成。

安装包由 `Windows standard installer` 工作流生成，附安装、启动、升级保留配置、卸载保留数据的回执。回执不代表真实模型调用或客户项目已验收。

本轮采用前端构建、页面实际检查、Cursor 定向用例和一次 Windows 安装流程检查，不运行全仓复杂测试。客户项目的模型连接、环境启动和业务结果仍需在对应电脑上实际使用确认。
