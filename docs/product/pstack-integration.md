# pstack 内化与知识记录

参考：[cursor/plugins/pstack](https://github.com/cursor/plugins/tree/6b0300214a09fd6029cfb7077043125758cd1fd2/pstack)，读取版本 `6b0300214a09fd6029cfb7077043125758cd1fd2`。

本项目把适用原则写进自己的任务提示和现有知识流程，不要求使用者安装 pstack。没有复制其技能源码、指定模型配置或自动化脚本。

| 参考原则 | 在本项目中的行为 |
| --- | --- |
| recall | 接续时先核对已有任务记录和当前代码；已有完整交接就直接继续。只读当前任务范围。 |
| sequence-verifiable-units | 拆成小步，检查实际受影响行为；通过后继续交付。 |
| prove-it-works | 写明实际操作和结果，保留工单、运行、提交或文件依据，标明未验证项。 |
| encode-lessons-in-structure | 能落到代码、类型或检查中的重复规则直接修正；需要判断的经验保存为待确认记录。 |
| subtract-before-you-add | 优先复用和简化现有实现，不默认叠加复杂流程。 |

分析、方案和开发结果末尾包含简短“知识记录”，随既有运行结果保存。知识库的“经验记录”可填写标题、适用场景、原因、做法、验证依据和注意事项，使用既有 `/api/memory` 和经验账本保存、搜索、读回。记录最初为待确认，不将模型叙述当成已验证事实；原有确认、共享和项目范围规则继续生效。

本次没有引入 pstack 的多模型并行评审、自动循环或全量测试要求，没有扫描个人 Cursor 会话，没有修改全局技能。使用者在“确认与管理”中决定经验是否用于后续任务。长期知识仍与原始运行产物、业务验收分开记录。
