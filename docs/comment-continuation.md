# 从评论继续任务

任务页统一使用“评论并继续”。系统保留评论全文，模型依据本次输入选择回答、分析、方案、开发或推送；不再简单重跑上一种模式。任务正在执行时，新的评论排队等待，避免同时修改同一任务。请求编号和持久回执防止网络重试重复启动。

开发前自动完成以下准备，进度显示在任务页和运行详情中：

1. 定位项目源码。空目录根据用户提供的仓库地址获取源码；缺少地址时返回具体缺项。
2. 沿用已有 Git 历史。无基线时建立本地首次提交，排除运行文件和疑似凭据，原文件保留。未提交的旧工作树通过恢复快照续接，不丢弃已有改动。
3. 通过已配置的 CLI 准备依赖及便携构建工具。优先已有工具、wrapper和锁文件；工具路径只应用到任务进程，不修改全局代理或登录状态。实际运行版本检查，准备失败时在同一任务内修复一次后再检查。
4. 在独立工作树执行开发、构建检查和诊断。原代码的构建失败保留为基线证据，不再成为跳过修改后验证的理由。

例如，评论“请推送到 origin 分支 feature/review”。仓库及分支必须逐字出现在这次评论中；历史聊天、模型猜测不能代替本次授权。平台核对开发结果与验证记录，生成开发提交并执行普通 Git push。非快进推送会失败，不强推、不自动合并、不替人验收或关单。缺少登录授权或远端拒绝时，保留本地成果并显示实际原因。

便携工具安装使用当前进程权限。已有租户隔离、开发确认稿、固定版本和人工验收约束保持；这些约束未满足时，页面显示阻塞原因，不把未执行描述成成功。
