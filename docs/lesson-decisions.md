# 经验人工决定与版本绑定

知识与记忆、经验复盘两个入口共用同一决定协议。确认只能将候选经验变为在用；恢复仅用于停用或暂停经验，必须填写原因。停用同样需要原因。正文编辑保留既有状态政策：编辑在用经验仍为在用，本次不把历史在用状态补写成当前正文的人工确认。

## 阅读、提交与回执

先以当前个人会话读取 `GET /api/projects/<key>/lessons/<lid>`。返回完整 `card`、`expected_token` 和 `content_digest`，卡片与版本来自同一份加锁材料。项目记忆列表和原经验复盘列表也附带同样的 `snapshot`。普通项目成员不能因此读取原本无权访问的全局记忆目录。

四种决定 `confirm/restore/retire/edit` 必须携带所读 `expected_token` 和稳定 `request_id`；可同时提交完整文本 `fields`，编辑与状态决定只发生一次原子登记。`reason` 与旧别名 `why` 同时存在时必须逐字相等。

HTTP 还要求 `X-Webuddy-Lesson-Actor: encodeURIComponent(阅读时的账号)`。该值只用于和实际个人登录身份比较，不能授予身份。租户网关把它与实际 actor、租户、路径、正文和授权上下文一起签名。另一标签页切换账号后，旧页面决定返回 `409 lesson_identity_changed`，不会记到新账号名下。Agent、共享令牌和个人工具连接不能完成这些人工决定。

服务端在同一账本锁内核对版本、查找原请求、计算状态和发布回执。相同账号、相同请求号与相同完整意图的重试返回原回执及**当前**卡片；换正文、版本、项目或动作复用请求号会冲突。原确认之后若已停用，重放不会恢复使用。`superseded` 表示原决定之后已有改变，不能把旧回执当作当前有效状态。

## 失败与浏览器恢复

- `400 invalid_lesson_decision`：请求格式或必要身份绑定缺失，未提交有效决定。
- `409 lesson_changed/lesson_state_conflict/request_id_conflict`：重新读取并明确复核，不能自动换号重发。
- `409 lesson_history_unreadable`：旧材料或新封套无法完整核验，原字节保留，不自动修复或忽略记录。
- `503 decision_outcome_unknown`：落盘结果不确定，只能核对原请求，不能新建一个相同决定。
- `503 lesson_storage_unsupported`：当前平台不支持本批验证的持久化方案，未发布本次决定。Windows 新写链路明确拒绝，不宣称已支持。

浏览器按实例、租户和账号隔离原请求与草稿。未知结果只能重放原编号及原正文；页面刷新后保存的回执也要向服务端重新核对。权限或账号变化会清除页面中的旧数据。重新打开新版前保存旧稿，旧稿不会自动套用到新内容。两处页面保留完整适用条件、不适用条件、备注、文件、来源与原始记录；使用提示不会覆盖真实适用条件。

## 持久化和发布边界

新的 `kind=human_decision` 记录同时包含决定与回执。POSIX 下在原锁内写临时文件、同步文件、原子替换并同步目录；原日志前缀逐字保留。无变化编辑仍有回执，但不消费内容版本、不清除已采用 revision、不重置使用计数。使用统计保持独立于人工决定版本。

旧程序 `01290b8` 不识别新封套。**产生新决定后禁止直接回切旧读取器**，否则新停用等决定会被忽略。发布失败时保留最新数据并停止服务，使用能读新格式的修复构建恢复；不得用旧备份覆盖后来写入。发布前在完整私有副本验证旧账本兼容、原库 schema/行不变和文件清单；真实生产知识不用于合成人工确认测试。

当前方案每次决定复制现有日志，成本随日志大小增长；没有宣称无限规模、历史损坏自动恢复或 Windows 原生持久化支持。该机制保障知识决定可追溯，不单独证明组织净收益。
