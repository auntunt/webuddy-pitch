# 固定候选的合成机制演练

入口在项目的知识评审页，名称为“合成机制演练”。它用于核验一轮实验的输入、预算、身份、取消和证据是否相互绑定。当前执行器只运行服务器内置的三个合成任务族；它没有接入真实模型，也不能证明知识改进或组织收益。

## 操作与结果

1. 从经验目录固定候选修订。保留完整修订编号，指定当前项目的材料保管人、候选优化人和结果选择人。
2. 项目管理者创建草稿。草稿冻结候选、当前基线、完整检索输入、任务、答案和固定输出。三个角色可以是同一人，报告会保留已知接触人，不因此声称盲评。
3. 管理者封存合同。系统再次核对材料和权限，在同一个事务中登记唯一批次、全部计划槽和原始期限。每个任务按基线、候选两臂运行，重复 1–10 次，总调用数固定为 6 × 重复次数，并发为 1。
4. 具有现有执行权限的管理者启动。每个槽先登记运行及预算，再持久化派发意图，然后启动一次真实受监管子进程。所有输出和清理回执保留。首次失败或未知结果停止其余槽。
5. 查看全部计划槽和结果。失败、未知、未执行的槽仍留在分母中；重复次数不增加独立来源数。`mechanism_passed` 仅表示机制演练通过，真实来源数为 0，实际费用和 Token 为未测量。

期限从封存时开始，包含等待启动的时间；页面刷新、重试和重启不延长它。当前进程同时按绝对时间和单调时钟取更短的剩余预算。重启后不能证明旧单调时钟锚，恢复只核对并收尾，绝不续发计划槽。没有足够停止证据的意图标为未知，保留预留额度，不能换批次重放。

## 权限与人工决定

材料保管人只有在账号仍有效、账号 epoch 未变且仍有项目读取权限时，才能读取完整材料。普通管理者、优化人和选择人默认只看到摘要；主动查看受保护材料会记录该人及其账号 epoch 的接触事件。工具连接始终只返回安全摘要，不继承创建者的材料托管权限。

新租户可以在授权范围内登记普通目录的实验元数据，但没有现有宿主执行权限时启动仍被拒绝。Git 来源继续核对真实提交；损坏、不可读的 Git 标记不能降级为普通目录。

已封存修订及其显式后代不能另起手工评审、修改或采用来绕开实验账本；封存也会拒绝仍在执行的同修订、祖先或后代手工任务。普通兄弟修订和旧终态手工记录保留原流程。已持久化的历史人工投影回执仍可完成原补账。合成报告不能用于新的生产知识采用，Agent 不能替人确认、验收或关单。

## 请求、存储与兼容

写请求返回与原请求编号、动作和合同绑定的安全回执，页面随后单独读取视图。视图读取失败只允许重新读取。网络中断不能证明写入失败，页面保留同一身份、账号 epoch 和完整原请求，必须显式核对原请求；只有服务器确证事务已回滚且没有此前回执，才允许替换意图。

新增四张表：`learning_experiments`、`learning_experiment_assets`、`learning_experiment_slots`、`learning_experiment_events`。运行、输入、步骤归属与预算预留在同一个写事务中登记。锁顺序为授权锁、Store 事务、必要的账本锁；不持有这些锁等待子进程。

实验运行从交付统计、个人习惯和执行器健康判断中排除。所有公共读取先分类再投影；损坏或不完整的实验关系明确拒绝，不能退回原手工全文接口。

部署必须验证精确候选、旧数据及模式保持、新四表迁移和原流程兼容。出现无法安全解释新账本的故障时停止服务、保留最新数据并使用兼容版本修复，不自动切回忽略新实验归属的旧程序，也不用旧数据库覆盖新写入。

真实模型同一性、可核验成本、总支出硬门、独立真实任务和生产提示词等价性仍是后续实证的前提；Windows 执行与跨平台锁语义也需单独验证。本功能不把这些未完成项报告为通过。读取和界面的细节见 [读取与界面边界](learning-experiment-views.md)。
