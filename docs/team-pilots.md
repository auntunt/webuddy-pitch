# 团队试点

从项目页进入 **团队试点**，或从工单的 **登记本次投入 / 团队试点** 进入。使用租户内个人账号；工具连接、共享令牌和自报姓名不能代替本人。此功能记录组织协作试点，不运行模型、不改变工单状态，不代替知识采用、技术验证、业务验收或关单。

## 协议与本人确认

项目经理可先保存不完整草稿。真实项目版本、参与者、日历、质量目标或模型预算未确定时保留空值，页面逐项提示。模型预算仅为人工声明，不授权模型调用，也不证明计量或实付；不要填写建议金额冒充已批准预算。

协议登记目标、版本依据、对照及纳入规则、个人与职责、观察阶段、固定任务全集、复杂度、数值目标、后续观察终点和退出/缺失规则。日历采用中国时间，劳动时间需携带明确时区。历史基线属于人工声明，系统不核证其独立性或可比性。

冻结需要至少两名当前可写个人，分担不同职责并覆盖需求、研发、测试、交付和运维；完整对照和至少两个分离的试验周期；全部参与者对同一版本自行确认。前后对照的基线须早于试验；并行对照须覆盖两个周期。冻结必须早于首个试验日。

经理不能代签。撤权重授或账号代际变化使原确认失效，无关项目权限变更不使本协议的确认失效。冻结后 **开始记录** 仍会重新检查来源及全体确认。资料补齐、日期到达或确认完成都不会自动开始。

每次协议修改都另存草稿，旧正文、完整工单来源、讨论、合同与引用不被覆盖，也不继承旧确认。来源变化需要另存并重新确认。新草稿不会把旧活动协议的投入移走；可在版本选择器打开旧活动协议，继续记录其投入或明确结束。旧版不能借当前版本的确认冻结或开始。

## 本人实际投入

参与者只能填写本人约定职责、固定任务和实际劳动。包括开始时间、实际分钟、活动、完整说明和证据引用。等待另列，不作为劳动分钟。单条记录最多一天；0 分钟必须本人说明原因，未填继续为未知。

发生时间决定阶段。阶段外或跨出任务阶段边界的整条劳动完整保留为未分配，不填补阶段内缺失；需要本人拆分或追加更正，不自动分摊到多个周期。事后记录、结束后补录分别标明。每次更正追加并引用原条目，仅能更正本人的同试点、同协议版本有效条目。不同试点或修订不能借更正搬走旧成本。

同一租户内，本人各试点有效劳动时间段不能重叠。更正失败或并发冲突不会先作废原条目。页面保留输入，结果未知时沿用原请求核对；收到回执后详情读取失败，只需重新读取，不重复登记。

## 阶段报告与截点

报告保留固定全集中的全部任务，包括失败、退出、未完成、来源不可用和验收观察未成熟的任务。经理登记退出需写原因，不会删除分母。结束记录也不表示样本完整或观察成熟。原验收后 14 天返工观察线保持。

报告分列本人已申报分钟、阶段内和阶段外投入、事后记录、等待及逐任务职责缺失。**存在一条记录不代表全部投入已填齐。** 本批没有逐人完整填报或 NA 确认机制，完整性始终为未知，不自动计算组织收益百分比。实际模型费用未知时显示未知，点数不代替供应商账单。

每个报告包含服务端生成的观察时间、协议版本及摘要、原事件编号范围和完整快照摘要。劳动发生时间与登记时间分别保留。后补、更正、来源改变或 14 天观察成熟会形成新截点；旧下载文件不被覆盖。请保存每次完整 JSON/Markdown 导出，按其中的来源和事件范围复核当时已知事实。Markdown 保留完整 JSON 附录，原文不会为排版而裁掉。

本功能可支持真实试点准备与过程记录；合成测试账号的流程通过不证明真人参与或组织收益。真实项目、人员、目标、日期和预算应由实际负责人及参与者确定。


## 怀柔首轮任务与验收记录模板

当前为准备材料，尚无怀柔真实项目通过或提效结论。建议首轮纳入 6—10 个真实任务、至少两轮使用，数量不是成熟度门槛。ERP/公开样例只能标为演练。

对照：A 使用当前工具/模型/方式；B 尽量保留方式，换约定模型通道；C 使用 Webuddy，模型及配置与 B 相同。优先保障 B/C 可比：同任务从同一初始代码开始、业务信息一致、各组不借前组答案，记录工具、时间、调用预算与无法控制的差异。

复制下表填写到既有试点任务记录与证据附件；未知项留“待补充”，不要由实现生成自己的正确答案。

| 字段 | 记录 |
|---|---|
| 项目/任务/组别/轮次 | 待补充；演练或真实项目须明确 |
| 业务要求与本人确认 | 规则/合同/独立人工依据、确认人、修订、时间及来源链接 |
| 版本与环境 | 初始完整 SHA、候选完整 SHA、环境/数据/测试配置版本 |
| 范围 | 新增或修改行为、受影响旧功能、必须保持约束、排除项 |
| 逐项证据 | 业务要求 ID、输入数据、独立预期、实际结果、具体测试及原始报告/截图 |
| 缺口 | 失败、未执行、受阻、未覆盖、失效及原因；下一责任人 |
| 人工投入 | 环境准备、理解需求、设计、Review、补测、确认、返修、Leader 复核分别记录本人实际分钟；等待另记 |
| 模型调用 | 模型/版本/配置、调用预算、供应商实际用量与原始凭证；可核对费用或未知，不用平台点数推算 |
| 业务结果 | 本人验收、后续漏检/返工、退出或未完成原因及观察截止时间 |
| 可比性 | B/C 相同条件、偏差与影响；失败和退出保留在固定任务全集 |

模型收益观察 A/B，平台增量观察 B/C。先报告逐项业务结果、漏检/返工和全部人工投入；不能把测试数量、录屏、定位 precision/recall 或 AI 自评改称业务正确率或节省工时。未取得真实源码、规则、数据与验收人时，本表保持准备状态。

首轮选题可从[广联达 POC 场景与澄清问题](../examples/client-tickets/广联达POC场景与澄清问题.md)开始，由甲方选择并补齐规则；这些是题库，不是已确认的怀柔算法。每次实际 Review 的有效问题、误报和人工发现沿用[验证与 Review](verification-review.md)记录，再将证据链接填入上表，避免另造统计口径。
