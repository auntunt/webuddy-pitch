## 页面与入口

| 新入口 | 保留与整理的能力 |
| --- | --- |
| 工作台 `#/workspace`，空路由默认进入 | 我的责任任务与待复核任务合并，团队视图、真实分页、阶段筛选；交接记录按需打开，原交接深链接保留。等待原因复用 stage、candidate、verification，运行中任务单独分组。 |
| 需求与变更 `#/tickets` | 搜索、状态、指派与未关闭筛选；按已读取列表分页，明确 500 条接口上限，返回后保留查询。原看板、需求对话、重构工单仍在次级导航。 |
| 任务 `#/t/<key>` | 按阶段默认选择验收依据、需求与范围、变更与记录。页签移动原控件，不重建输入；原 `/prompt`、`/runs` 深链接保留。业务实测表及证据包逐项确认依据、范围、报告、AI Review、人工记录分别呈现。 |
| 验证与交付 `#/deliveries` | 复用现有交付记录，并直达候选复核、验证运行、版本发布。没有创建新的交付状态机。 |
| 项目知识 `#/memory` | 沿用现有业务主题、搜索和来源；知识页、业务代码图谱、状态图、参考资料、经验复盘、交接入口保留。 |
| 项目与环境 `#/projects` | 项目任务、协作与工具保留；管理员复用 readiness 分组查看记录、执行、验证、发布的条件。普通成员说明由管理员维护，不把接口拒绝解释成项目不可用。 |
| 次级管理与账号 | 运行记录、流程统计、客户、设置、成员权限保留；额度移入账号菜单。执行器、测试机沿用设置入口。 |
| 登录 `/login` | 居中表单、统一 W 标识；真实 POST 认证、飞书配置、组织流程、安全返回、密码显隐和错误恢复保持。 |

- `/api/workspace` 增加可选 `attention` 视图，以及 `attention_count`、逐行 `attention_reason`、`running`。旧视图与原 `counts` 保持兼容。计数在分页和可见页详情投影前计算；授权范围继续由服务端限定。
