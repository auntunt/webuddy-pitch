# 合成机制演练的读取与界面边界

本功能验证固定实验计划、预算、取消和证据登记机制。所有结果都标记 `rsi_qualified=false`、`production_prompt_equivalence=false`，不能作为真实项目收益或人工采用依据。真实费用和 Token 未测量；合成单位另列。固定重复次数不会增加独立来源数，失败、未知和未执行的槽不会从计划分母删去。

实验目录与详情供当前项目成员读取安全摘要。摘要包括固定候选和基线修订、来源提交、三个真实角色、已知接触人、完整预算、任务族、选择与停止规则，以及全部计划槽。普通管理员不会因管理员身份而自动取得答案、输出或冻结提示词。

完整材料只向当前真实材料保管人或已明确登记本人查看授权的人返回。保管人必须仍有项目读取权限，且账号 epoch 与实验登记一致；删除后重建同名账号不会恢复旧权限。显式查看授权绑定本人、账号 epoch 和具体资产。某一运行或批次涉及多项材料，必须具备全部相应授权才返回全文。工具连接即使由保管人创建，也始终只有安全摘要。旧单实例显示名不能冒充租户个人身份。

工具身份由受限凭据及网关签名绑定，`X-Webuddy-Agent` 仅为工具标签，不会把工具升级为个人保管人。真实个人会话已有的读取权限也不会因为自行附带该标签而被重新定义。平台不声称能够阻止有权阅读材料的人主动把材料交给外部 AI；这类材料不能因此被宣称为独立未见。

读取集中在 `learning_experiment_views`，覆盖实验、批次、运行、修订历史、人工决定和目录中的重复副本。读取不启动迁移、恢复、进程探测或当前性校验；已登记状态不等于当前可采用。受管关系不完整或跨项目矛盾时拒绝读取，不能回落到手工运行的完整输出路径。

受管批次通过封存时原子创建的新批次和计划槽分类。旧手工批次即使使用同一修订，也保留原来的完整历史。已经看过的旧材料不会因为新实验封存而变成“未见过的留出样本”。新的手工执行或采用受管修订由服务器单独拒绝。

登录诊断、个人习惯统计和日常运行待办在 SQL 分页、输出分类或指纹生成之前排除实验运行。它们不以合成失败诊断真实执行器故障，也不把受保护的提示词用于个人行为分析。

界面单独显示“合成机制演练”。创建草稿、封存、启动、停止和主动查看材料均为明确操作，不由页面刷新触发。权限按钮按当前租户和项目权限收紧，提交时仍由服务器重新授权。未知结果保存被冻结的请求体和请求编号，只能按原请求核对；不能修改意图换号重发。原请求核对回调只能发送仍存在、同主体且同请求号的未知记录；已完成、已删除或被后来新意图替换的旧回调不会发起写入。保存请求失败时不提交。身份、租户或权限变化清除旧材料，旧响应不能写回新主体的页面。

未确认写入的原请求存放在独立的浏览器会话记录中，与页面缓存分开。服务器在当前个人通过项目授权的 GET 中返回其 `request_identity`（租户、真实账号、账号 epoch），界面核对身份后才读取对应项目的原请求；工具连接和旧单实例返回空身份，不能恢复个人请求。同一账号的权限上下文更新不会删除或换绑原请求；换人、换租户及同名账号重建不会展示旧人的记录。权限清屏仍删除页面材料和内存记录，旧响应不能清除另一上下文恢复的未知意图。重新授权和刷新只恢复记录，不自动重放；必须明确点击原请求核对，服务器再次验证当前权限。该本地记录不取代服务器授权或永久审计；关闭会话或主动清除浏览器存储仍会移除它。

写操作只返回安全回执，包含原请求编号、动作、实验编号和合同摘要。界面核对并保存回执后才单独读取视图；视图读取失败仍显示“操作已登记”，只能重读，不能重发写入。普通 HTTP 4xx 不能证明原请求未提交。只有服务器明确返回 `experiment_not_written`（原请求确证未提交且事务已成功回滚）时，界面才允许修正输入并另发请求。

这里保留的是隔离副本的设计与代码说明；测试、独立审查和发布是否完成，以该批实际验证记录为准。

## 详情与目录先分类后读取

受管详情由 `managed_detail` 在旧详情入口之前识别。目标受管时，整个回包从账本读取并按当前个人权限投影；不读取 Git、工作区证据或活动知识状态，不把已登记通过标为当前有效。`None` 只证明目标未受管，不证明其整段历史都普通：目标保留原有现场核验与手工流程，任务先分类，历史及决定最后逐项投影。封存兄弟修订不能连带禁止该目标。归属矛盾和部分模式返回错误，不能降为普通记录。历史中的旧手工任务仍保留原全文，不因后来封存同一修订而伪装成新的留出材料。

目录使用 `catalog_revision` 在 `revision_current` 等现场判断前识别受管修订，并使用 `catalog_jobs` 在旧任务描述前按真正任务归属分类。受管目录显示“受管实验历史，未核验当前来源”，`stale=null` 不是有效声明。普通任务仍使用原本只描述冻结输入协议的纯账本说明；受管任务不进入该分支。无授权投影的调用方遇到受管记录必须明确拒绝，不能回落旧全文路径。

当前代码的 `learning_runs.get` 本身已经只读，不会恢复或过期任务；本轮问题在于旧详情先执行 `revision_current`、来源绑定等现场读取，再做受管投影。修复避免先读后遮盖，没有把未观察到的恢复写入声称为已证实问题。RSI-1 的独立捕获修复已纳入实仓提交 `3705caa`；本文对应的 RSI-2 隔离副本已完成下述定向验证，尚未集成或发布。

## 本轮定向验证

在隔离副本串行执行 DTO 20 项、真实 JS 22 项、实际 API handler 17 项和既有 UI 兼容 22 项，共 81 项全部通过，0 跳过，6.424 秒；源码/测试执行前后哈希一致。旧源码上的真实修订编号、重复重试与未知请求持久化共 8 项反例均命中原缺陷，完整失败证据保留。联合首轮 DTO 夹具缺新候选归属字段与 create/seal 锚导致 8 个错误，补齐真实登记结构后通过，全部断言 AST 保持。真实修订编号由后端精确查询，前端仅校验非空且不改写原字符串，不再误限为 32 位十六进制。

这些是合成数据的定向验证，不代表完整系统全量、真实浏览器、真实模型或生产环境已经验证；发布仍由根任务统一收口。


## 项目内入口与实际页面回读

当前已授权项目详情提供“分类与评审”直达该项目的窄读取入口；不会改用组织聚合 `/api/memory`，其管理员限制保持原样。点击时绑定已展示项目，迟到旧页或已移除项目不能切换或读取另一范围。演练操作收到完整回执后，独立 GET 成功显示“当前记录已读取”；GET 失败仍只允许刷新，不能重发 POST。

首轮实际 Chrome 合成验收验证了 6 个固定子进程、390 像素布局、manager 摘要与 curator 完整 CRLF 内容、普通兄弟修订控件，以及真实提交后回包中断的原请求恢复。其证据只支持合成机制，不支持真实收益、独立留出或 RSI 资格；第二轮已使用修复后的冻结源码，从普通成员的正常项目入口完成相同六槽执行与原请求恢复，源码前后校验一致，全部临时资源已回收。
