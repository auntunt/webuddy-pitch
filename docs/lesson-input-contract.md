# 经验输入、运行回执与手工评测

经验进入团队执行器前，平台先选择允许使用的卡片，再冻结实际知识块。普通运行和手工经验评测共用 `lesson_input` 的选择器与渲染器。它们使用相同的知识块协议，但任务提示词、工具权限和执行目标不同；手工回答评测不能证明软件交付或组织收益。

## 选择与原文

保留原检索范围与排序：最多500张本项目卡、原1500字符工单/3000字符补充匹配窗口、本项目优先、最多一张共享卡。先选择，再检查固定修订是否仍可用；过滤后不补位。既有留出分组保持。

匹配窗口只用于检索，不限制被选中经验的输出。JSON知识块保留完整标题、现象、原因、改法、验证、反例、适用条件、不适用条件，以及已有备注、diff和文件列表；缺键、null、空串、换行和重复文件项各自保留。JSON转义可逆，不改写资料中的模板字符或分隔符。资料始终标明为参考数据，不能扩大执行权限或代替人工确认。

`lesson-renderer-v3` 在完整JSON后提供同源的中文字段阅读索引，保留“根因：…”等原有可读格式。索引只复述同一载荷中已有的字符串，不单独保存另一份正文，不把缺键或null转成空串。完整JSON仍是权威记录；索引全文同样计入最终提示词字节数、哈希与评测预算。v2渲染回执不能冒充v3输入。

跨项目只使用人工明确发布并由消费项目允许使用的公开视图。旧分享协议未公开的条件、备注、diff和文件不会从私卡补齐；旧协议在发布时已经形成的正文范围保持，完整私卡与公开视图不能混称。

## 实际运行回执

选择、渲染与绑定在同一个 Store → 账本锁窗口内完成。`context.json` 保存完整载荷、渲染版本、正文哈希、来源版本和共享授权生命周期。回执保存失败时不启动执行器。

每次子进程尝试保存完整 UTF-8 提示词、字节数、SHA256和传输方式。它证明平台提交的输入，不证明执行器或模型已经阅读、理解或遵守。没有配置提示词传输的自定义执行器明确标为 `none_configured`。

经验改版、停用、共享撤回、消费授权撤销或关联来源变化后，旧会话和复制的旧结论不再复用。相同秒内撤销再授权也会失效。单纯使用统计变化不改写旧输入，也不使其自动过期。相关历史存在但缺少完整回执的旧工单运行不能冒充有效新回执；没有学习历史的旧会话保留原兼容规则。

执行结束时再次核验知识来源；变化时保留原结果并标记本次失败。固定版本检查在清理受管工作树之前核验，随后继续原有代码未变证明及清理，不能把正常清理误判成来源变化。

## 手工回答评测

新经验评测冻结完整选择池、授权、选择理由、两臂实际输入和最终提示词。候选仅在实验副本中替换，不写回经验账本，不赋予人工采用状态。候选未被真实选择器选中时，记录没有实际干预，不强行塞入。

两臂最终提示词默认各限65536个 UTF-8 字节。任一臂超限时整对不执行、模型调用为零，保留完整输入、原因和原分母；不截断资料或静默丢弃失败样本。

结果作用域为 `manual_exploratory`，`production_prompt_equivalence=false`、`rsi_qualified=false`。未知或损坏协议拒绝执行，不宣称具有当前渲染器保证。普通人工评测及合法人工采用仍可用，不能将它们升级表述为自动改进收益证据。

旧 v1 待运行/排队/恢复任务转为既有 `stale` 状态，原因 `input_schema_expired`，释放活跃位置；不删除原轮次和结果，不抢占仍持内核锁的工作进程。已完成旧结果按旧来源协议核对，可保留合法人工采用，说明其 legacy/manual 范围。

## 历史与发布

新 `lesson-content-v2` 修订保留缺键和null；旧修订、指纹、幂等请求、投影和历史解释保持旧协议。修改提案合并父修订，不隐式删除已有字段。历史不补造人工确认，人工决定权限、状态迁移和guard不放宽。

旧程序不理解新投影协议；上线后发生故障应停止服务、保留最新数据并使用兼容程序修复。不可用旧数据库或账本覆盖用户后续写入，也不可自动回切不理解新协议的reader。

本批不证明真实付费RSI、独立终测集、累计预算、可信模型成本或跨角色团队收益。上述条件未满足前，付费自动改进试点保持关闭。
