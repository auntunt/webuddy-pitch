# 工作台与任务交接

工作台把任务、当前负责人、下一责任人、交接材料和已有代码证据放在同一页。交接是协作记录：接收材料不会更改工单负责人、独立复核人、技术验证、业务验收或关闭状态。

## 日常使用

1. 用个人账号登录，打开“工作台”。“我负责的”包括自己负责的任务和下一步由自己处理的交接；“待我接手”只列等待自己接收的交接，也保留接收前已标阻塞的记录。
2. 选择任务，阅读完整需求、现有技术/人工状态和来源依据。发送时选择需求、研发、测试、交付、运维中的交接目标阶段，指定有效个人账号，写明目的和完整材料。
3. 接收人核对材料后点击“接收材料”；材料不足可以填写原因退回。当前下一责任人可以填写阻塞原因，解决后恢复。恢复待接收状态时保留原始待接收起点。
4. 接收后可以再交给另一位成员，例如研发交给测试、测试交给交付。发送人或当前工单负责人可以填写原因撤回尚未完成的交接，处理账号停用或来源变化等情况。
5. 技术复核、合并和业务验收仍通过原任务/团队入口进行，保留原有证据门槛和个人确认要求。交接页面不会替代这些操作。

同一任务只有一个当前交接。历史交接和每次操作的操作者、完整说明、时间、状态均保留。工作台每页 30 项，阶段计数取完整筛选结果，不以第一页代替全部任务。搜索包含需求正文、责任人和阻塞原因。

## 记录的含义

| 内容 | 定义 |
|---|---|
| 当前负责人 | 既有工单负责人；接收交接不自动改派 |
| 下一责任人 | 当前交接中要处理下一步的人；未登记交接时按既有任务/复核状态展示 |
| 交接阶段 | 发送时明确登记的目标环节，不证明接收人已开始执行 |
| 等待时长 | 待接收或当前阻塞状态的实际登记时间；历史无记录时为未知 |
| 已接收/已退回/已撤回 | 当前不在等待；不代表任务已经验收或完成 |
| 来源依据 | 发送时冻结的完整需求、项目路径、项目引用、分配及具体候选提交/证据 |

现有“我的/团队”是责任视图，仍采用现有共享工作区访问规则，没有新增项目 ACL。交接快照不是人工验收证据。没有候选时可以交接需求材料；存在候选时必须能核对当前候选。候选已失效的任务需先更新候选或通过原分配/讨论入口处理，不能用交接复活旧证据。

## 变化与重试

需求、项目路径、引用授权、固定版本、负责人/复核人或候选证据变化，会使原交接过期。页面显示原因，拒绝接收旧依据，但允许退回或有理由撤回。尚未发送的草稿会保留，需要用户阅读新依据后明确重新绑定。

提交时会固定请求编号和完整内容。双击、断网或返回内容不完整时，页面保留原请求供重试，不新建一条不明结果的重复交接。已登记但候选详情读取失败时仍返回成功回执，并提示重新读取详情。交接、时间线、审计和重试回执在同一事务提交；并发冲突要求刷新，不覆盖其他人的更新。

个人账号停用后，旧签名会话不能继续操作；历史署名和说明仍保留。共享服务令牌、显示名和 Agent 请求不能代人发送或接收。

## 本轮范围

本轮连接真实任务工作台及跨角色交接，不新增自动派单、通知外发、定时执行、自动验收、自动采用知识或组织效率收益指标。浏览器和全量验证使用临时合成项目，不能据此证明真实模型评审可用或实际组织效率已经改善。
