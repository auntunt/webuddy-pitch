# 知识分类与评审使用说明

入口：**知识与记忆 → 分类与评审**（`#/memory/learning`），先选择项目。

这里分别显示内容与来源是否有效、机器验证结果、人工决定。机器通过不会确认工单、关闭工单或批准发布；同名知识与来源项目的确认也不会自动成为另一个项目的确认。

## 三类内容怎样处理

| 类型 | 操作 | 通过意味着什么 |
| --- | --- | --- |
| 项目事实 | 固定完整正文和源码证据 → 独立评审 → 必要时有限修订 → 人工采用 | 该修订的逐条结论有固定证据支持；仍需人工判断业务适用性 |
| 可复用经验 | 补齐现象、改法、验法、适用和不适用条件 → 固定用例 → 基线/候选成对评测 → 人工采用 | 候选在这些文本/JSON 断言上改善且没有规定的回归；不代表实际代码已正确修改 |
| 执行策略 | 创建允许范围内的参数候选 → 跨场景成对评测 → 人工采用 | 候选在固定输入、断言与字符量约束下通过；不代表统计显著或生产效果已证明 |

历史知识页和经验卡继续保留原记录及状态。历史人工确认不会被补写为机器通过。读取目录和详情不会启动模型、恢复发布或采用建议。

## 固定修订与独立事实评审

1. 在项目事实中打开条目，选择“固定当前内容为修订”。完整正文、引用文件和 SHA-256 会与项目、工作区、Git HEAD、引用授权一起保存。未提交文件和非 Git 目录会明确记录为工作副本内容清单。
2. 打开固定修订，选择独立评审执行器。默认最多修订 2 次、模型调用 6 次、总时限 600 秒。评审和修订分别启动全新运行，不能借新批次重置同一事实修订的预算。
3. 查看逐条结论、引用位置、每轮完整输入、输出和错误。缺证据、冲突、无法判断、解析失败、超时与取消都不会算通过。
4. 如需修改正文，在原修订下保存新修订；原文与旧评审保留。程序生成的事实块和登记字段不能由修订 Agent 改写。已采用事实的下一草稿只同步已有的人工状态标记，不继承上一轮机器通过或人工采用。

严格冻结输入目前只接受能在本机证明具备相应隔离参数的 **Claude CLI**：关闭工具、MCP、hooks、项目设置、命令扩展和会话复用，并在空临时目录执行。不接受任意命令、额外权限参数或无法核验的执行器；Codex 的 `read-only` 仍能读取外部上下文，暂不用于这条严格评审路径。

普通知识获取仍可使用原有写入 Agent。批量 Survey 可通过 API 显式设置 `review: true` 和 `review_options`，在写成后另行登记评审；默认关闭，撰写成功与评审通过分别记录。旧 Survey 队列不是跨文件事务，若写页后、评审登记前服务崩溃，可能需要在分类页面手动启动评审；不会补造通过记录。

## 冻结经验和策略用例

用例需要唯一编号、完整输入、标准输出、验证器和明确的 `generation` 标记。页面首版使用 `contains_all`；API 还支持 `exact`、`json_equal`。可额外指定 `forbidden` 和 `scenario`。例如：

```json
[
  {"id":"retry-1","input":"合成场景：同一事件重复投递，应如何避免重复提交？","validator":"contains_all","expected":["事件编号","去重"],"generation":false,"scenario":"retry"},
  {"id":"retry-2","input":"合成场景：回调已成功，响应丢失后又收到同一事件，应如何处理？","validator":"contains_all","expected":["已处理","事件"],"generation":false,"scenario":"retry"},
  {"id":"distinct-1","input":"合成场景：不同事件携带相同业务内容，能否仅按内容合并？","validator":"contains_all","expected":["不能","事件"],"generation":false,"scenario":"distinct"}
]
```

这只是格式示例；应按真实项目补充可信的预期结果和反例。每个留出用例执行基线、候选两侧，各占一次调用。至少 3 个不同留出输入才可能通过；策略还要求至少 2 个场景，并证明参数实际改变了上下文内容。生成候选使用过的样本不能变成最终留出；更换编号、修改断言、改策略名称也不能绕过样本历史。

启动后用例、断言、模型、证据、基线、顺序种子和预算固定。标准答案不会放入模型任务输入；两侧完整答案留存，由程序执行断言。候选须满足全部断言、优于基线且无回归；提示长度上限为基线的 2 倍加每例 1024 字符固定开销，输出长度上限为基线的 2 倍。这里计量的是字符量，实际 token 和金额未取得时显示“未知”。

策略首版仅开放 `context_budget`，整数 **4000–12000**，默认 **6000**。每个项目只有一个生效预算槽；人确认权限、guard、状态迁移、证据绑定和共享授权不参与优化。策略评测与实际任务共用上下文过滤和预算渲染，过期的已管理事实不会成为效果证据。

策略回执绑定实际读取的工作区。固定提交的临时只读 checkout 使用默认预算，保留来源记录，不继承主工作区的策略采用；主工作区策略撤销或更换后，原冻结输入仍需重新准备。

## 人工决定、撤销和恢复

采用、撤销、重试人工发布和放弃未完成发布必须使用已登录的个人账号。共享令牌、显示名或 Agent 标记不能代替个人身份。

采用前服务器重新检查对应修订、机器通过批次、来源、当前人工指针和完整正文。两人同时操作同一版本时，过期请求返回冲突，不覆盖另一人的决定。新的采用仍落到原知识页或原经验卡，不复制一套独立生效记录。

数据库保存决定意图，文件记录保存幂等发布回执。中途失败时：

- “处理中”可以显式重试，沿用原决定编号和内容；已完成的文件投影只补数据库审计，不重发旧版本。
- 事实发布发生冲突，可核对当前现场、填写原因后放弃未完成发布。放弃保留正文及历史，内容仍待人工确认。
- 已采用的确切修订可以撤销；来源过期不会抹掉人的历史指针，仍可停止使用。
- 中断的模型步骤只有在监督进程、输出和清理回执完整匹配时才能复用。无法确认的调用不会自动重复；恢复不重置已用调用数或原截止时间。

后续任务记录实际注入的事实、经验、共享副本和策略修订，以及未注入的原因。来源变化、撤销采用或撤回共享引入后停止使用；关联的旧 Agent 会话和旧结论也须重新核对，不能仅凭新回执继续使用旧隐式记忆。参考项目的共享与使用方引入仍需分别显式授权。

## 当前验证范围

本轮工程验证使用临时仓库、合成回执及真实本地进程，验证隔离、截止时间、并发、恢复、授权和界面行为。本机原生 Claude 未通过执行器检查，**没有完成真实模型的事实核对准确率或任务改善效果评测**。

参考工作流项目可以浏览固定修订；独立模型运行首版沿用 development 项目限制。未启用定时任务、自动采用或组织级自动推广。真实模型试点、生产部署和 Windows 实机锁/进程验证需要各自的后续验证。
