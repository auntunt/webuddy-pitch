## 保留的失败与修复

1. 外部 Codex 的 workspace-write 沙箱不能监听 TCP，原 35 项运行均出现 PermissionError；写共享 Git worktree 元数据也被拒绝。没有删除测试、弱化沙箱或重试绕过。协调者在正常验证环境实测并提交，平台再次独立验证。`implementation-process/output.bin` 原样保留；退出码 0 不被解释为沙箱测试通过。
2. 第一轮平台测试夹具未忽略 `__pycache__`，编译产物被真实源码变化检查拒绝。修正临时夹具 `.gitignore`；保留产品版本变化门禁与原失败日志。
3. 独立复核复现并修复：共享令牌伪造操作者、预览配置变更仍沿用旧签收、预览原日志被覆盖、违背显式工单基线，以及另一服务进程关闭工单后提交把它重新打开。保留全部红绿日志；其中一次独立 fixture mock 自身错误也保留并注明。
4. 浏览器联调发现新 API 返回裸预览端口 URL 会 401，改为工作台授权入口并为真实 endpoint 补回归。之后正常授权重定向、真实浏览器操作通过，没有关闭浏览器安全保护。普通 Python CookieJar 不把 Secure cookie 发给 HTTP 回环的额外诊断失败不冒充应用通过。
5. 首轮全量 741 项中 1 项 CLI 有界等待失败；177 个源码/测试/构建文件前后相等。原全量日志不能区分当次超时发生于第几次 HTTP 请求；确定性时钟回归另行复现“截止后又轮询一次”的错误路径。修复后返回最后一次真实快照，不吞掉第一次读取失败、不取消服务端运行。原失败日志 `platform-full-final.log` 名称为首次运行时所设，不能当作最终绿灯；第二轮 `platform-full-after-deadline.log` 中 CLI 回归全部通过，但有另一项旧集成测试的事件顺序断言失败。
