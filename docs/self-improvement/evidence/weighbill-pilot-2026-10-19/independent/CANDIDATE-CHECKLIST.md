# 条件化台账编辑与审核：候选独立验收清单

准备于 2026-10-19。基线为 `60d6422ee898959557fc529a8e0335524b5ee2c0`。本文件是待验收行为清单，不是候选通过报告。基线缺口和真实执行证据见 `REVIEW.md`。当前尚未收到候选就绪通知，也未检查正在实现的源码。

## 接口边界

与主代理确认的协议为 `record_view.version`、PATCH 的 `expected_version` 和 approve 的 `versions` 映射。提供条件时严格校验，第一方台账始终发送条件。没有版本参数的旧 API 保留兼容，不能保证跨客户端防覆盖。

基线 `reproduce-stale-client-edits.py` 使用旧的无版本请求。候选如果继续允许这些请求，并不违反已约定的兼容边界；不能要求该脚本在新版本“变绿”，也不能用它作为新保护生效的证据。新验证须真正从 GET 读取版本再发送条件，并检查第一方页面遵守协议。

| 编号 | 可执行场景 | 必须观察的业务结果 |
| --- | --- | --- |
| V1 | 读取详情和台账列表；按返回 version 保存；再读取 | 对外版本是明确的非负整数，与成功写入对应；下一次条件使用成功响应的新版本 |
| V2 | A/B 同读 v；B 修改重量保存；A 以 v 提交旧全量表单 | A 明确冲突；B 的重量、当前版本和完整历史保持不变；不能新增 A 保存成功历史 |
| V3 | 条件包含 `0`、空值、布尔、字符串、负数、缺少映射键或非法映射 | 合法的 0 不被当成未提供；不合法的显式条件被拒绝，不能静默退为兼容盲写；错误响应不修改记录和历史 |
| V4 | 保留无条件旧 API 调用 | 兼容行为明确记录为保护范围之外，文档和验收结论不宣称所有客户端都受保护 |
| V5 | 服务端自身并发写入 | 既有 SQLite CAS 仍有效；客户端版本核对不能替代最终存储 CAS |

## 完整用户路径

| 编号 | 场景 | 必须观察的业务结果 |
| --- | --- | --- |
| E1 | A/B 同时打开；B 改重量；A 只改货名并保存 | A 收到可理解的冲突，完整草稿保留，页面不显示保存成功、不擅自跳下一单 |
| E2 | A 查看最新值并明确确认自己的变更 | 可以完成重试；未修改的旧重量不能自动覆盖 B 的新重量；有冲突的同字段必须显式选择或重新输入 |
| E3 | A 成功保存后继续编辑 | 当前详情和缓存版本同步，后续合法保存不因仍用打开时版本而冲突 |
| E4 | 打开详情、切换记录或页面时有迟到请求 | 迟到返回不能覆盖当前记录草稿、当前版本或按钮状态 |
| E5 | 保存发生网络错误或非 409 服务错误 | 草稿保留，按钮可恢复，错误不被解释为成功；重试仍带原有确认版本 |
| E6 | A 保存已提交但 ACK 丢失；B 随后修改；A 再试 | 重试不能覆盖 B；允许安全冲突或明确确认处理，禁止自动 GET 最新版本后重发原旧全量表单 |
| E7 | 冲突或不确定 ACK 后重试最终成功 | 完整历史显示真实操作人和前后变化；失败不伪造成功记录；没有无依据的重复成功或重复操作提示 |

E6 在基线中为明确建模的 ACK 丢失，未声称真实浏览器断网。候选报告也须区分实际浏览器操作、真实 HTTP API 与隔离处理函数执行。

## 审核

| 编号 | 场景 | 必须观察的业务结果 |
| --- | --- | --- |
| A1 | A 看 v；B 保存到 v+1；A 未编辑直接审核 | 旧版本审核被拒绝或明确 skipped；记录不能被 A 审核为 approved |
| A2 | A 编辑并直接点击保存/审核 | PATCH 成功后使用其返回的新版本审核，不能沿用详情打开时的旧版本；任何一步失败均不假称全部成功 |
| A3 | 批量审核含一个当前记录、一个过期记录 | 只允许当前记录通过；过期记录原状保留；UI 准确显示部分成功和 skipped，不能把整批显示为成功或无条件跳下一单 |
| A4 | 明确重新核对最新记录后审核 | 能完成正常审核，记录审核人和当前版本；核对动作不能悄悄批准未经用户确认的内容 |
| A5 | 非审核员、已审核后修改、空批次等既有流程 | 原权限与业务状态规则保持；编辑已审核记录后的未审核状态和历史仍准确 |

## 版本化预览路径

显式 `base_path` 默认空。配置非空前缀后，应实际打开页面并操作同一业务流程，验证页面资源、API、详情刷新、历史、下载/导出等相对地址不会逃逸至根路由。前缀健康响应不能代替业务验收。不得为该项接触原仓库实际数据或生产。

## 证据与隔离

- 候选使用固定提交、隔离克隆和新建临时 SQLite。记录原始请求、返回、操作前后 DB 版本及业务历史；不只保存通过计数。
- 复核前后记录候选 SHA、源码清单和 Git 状态。原仓库仅作基线来源，保持 `.DS_Store` 与 xlsx 原状。
- 对每个失败明确是代码缺口、测试假设错误还是环境问题。旧无条件接口的兼容行为单独记录，不混为第一方页面防覆盖失败。
- 本轮不扩展 OCR、签名框选、品牌视觉、生产或远端接入。
