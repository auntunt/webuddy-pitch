## 实际路径与改动

接续上一轮浏览器发现的真实丢失问题：工单填写未发送评论 → 全页刷新/服务重启 → 完整恢复 → 切换工单/标签页不串内容 → 显式发送 → 响应丢失后确认原请求 → 新写草稿保留 → 成功发送后清除已发版本。

- `ui_drafts.py` 用 sessionStorage 按工作区、操作者、项目、工单及创建身份保存完整评论。页面不自动传输草稿。恢复后保留换行、首尾空白、中文、emoji 和 HTML 字面文本；无长度截断。
- 待确认的原请求与正在编辑的新草稿分别记录。发送回执只清除相同版本的已发草稿；发送期间继续输入、切换工单、离开再返回均不清掉新内容，也不让旧响应跳回另一工单。
- `comment_receipts` 将评论、工单更新时间和请求回执放在同一 SQLite 事务中。请求按真实作者、工单及数据库隔离；重复确认返回原事件，不再写一条评论。同请求不同正文、身份变化或工作区变化返回冲突，原记录保留。旧调用不带新字段仍兼容。
- 评论发送后增量刷新讨论列表，保留评论框、验收说明、截图选择及附件说明的真实 DOM。页面显示草稿持久化范围和错误；配额写入失败不假报已保存，不发送尚未持久保存的待确认请求。损坏草稿不覆盖。
- 前端匹配服务器既有的 40 个 Unicode 字符请求身份规则，仅用于身份核对；完整界面用户名和评论正文保持不变。已登录时以实际登录身份为准，旧处理器不能继续发送。
