# 终端协作开发闭环

目标：选工单→Agent分析并分批追问→开发人员确认当前需求/设计/测试方案→开发→固定候选→测试/Review/CI→指定人员确认合并。CD继续独立，不自动生产发布。

验收：可恢复问答；精确修订确认；来源/回答变化使确认失效；Agent不能伪造确认；开发与候选入口执行确认门槛；现有复核和合并权限不放宽；CI绑定完整提交，未执行/失败不能通过；终端登录不把密码/会话交给MCP；已有工具连接不扩权。

现状：仓库已有push/PR CI、项目测试、外部候选和指定复核人fast-forward合并；没有统一终端澄清和个人确认链路，个人MCP也不能登记候选。采用新增develop权限、持久工单开发契约、独立人工终端交互和可配置GitHub CI门槛，复用既有执行/候选/合并。

状态：实现完成、验证收尾，尚未发布。按用户选择，由指定 Leader 批准当前证据，再由负责人在个人终端确认合并；旧任务继续原有复核人合并规则。现有业务验收与发布保持独立。

已验证：89 项开发/终端/原团队合并/项目测试回归；8 项 GitHub CI 判定；官方 SDK 的 19 项 MCP 协议与真实租户只读测试。开发合并使用真实临时 Git，测试/预览/CI 为明确合成边界夹具。实际租户网关支持 develop 问答，旧 scope 拒绝新增写操作。

修正：终端批准枚举应为 accept；开发操作分派须在执行器而非资源定位器；develop 权限必须同步租户运行时角色；来源变化不得保留旧回答。新增只读工具/HTTP 路由使固定数量断言更新为 19/205，没有删除权限断言。146 项回归中两项失败为新测试的不存在任务状态期望与路由数量，前者已复验，后者等待复验。

交付边界：平台只快进登记仓库本地主干，回执 pushed=false/deployed=false；项目远端推送/CD不冒充完成。协作开发连接不授予宿主执行权限。43发布与最终日志待追加。

最终本机复验：114 项相关回归通过（20.353秒）；43 项团队/终端合并通过（20.780秒）；启动互斥差异13项通过；真实签名会话登录与读取通过。原不存在工单应返回404，新测试改为精确404并另验跨租户401/403；新scope问答与旧scope拒绝的9项复验通过。数量有重叠，不相加作业务场景数。
