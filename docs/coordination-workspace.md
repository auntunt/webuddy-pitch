# 会议行动、任务简报与交付材料使用说明

这组功能把讨论、责任、下一步和交付材料放到现有项目与工单中。保存记录不会启动智能体、自动流转任务、代替人工验收或关闭工单。

## 从哪里开始

| 要做的事 | 入口 | 保存后的结果 |
| --- | --- | --- |
| 整理会后行动 | 工作台或项目页 → **会议与行动**，选择具体项目 | 保存完整会议原文和待补齐行动；逐项发布后生成既有任务 |
| 说明任务当前进展 | 工作台选择任务 → 交接详情上方的 **工作简报** | 保存一版结论、待决定事项和下一步，并保留对应来源 |
| 检查交付内容是否齐全 | **交付** → 打开交付记录 → **内容覆盖检查** | 为内容要求关联具体材料版本，记录本人核对的依据 |

请先用个人账号登录，并确认页面所在租户、项目。选择“全部项目”时，会议入口会要求先选定一个实际项目。

## 谁可以操作

拥有项目查看权限的个人可以读取记录；拥有项目贡献或管理权限的个人可以登记和修改。租户管理员按现有权限规则管理本租户项目。平台所有者身份本身不代替租户业务成员身份，也不带来业务验收资格。

负责人候选只列当前项目有效的可写个人成员。只读成员、已撤销的成员和智能体标识不能作为新行动的负责人。发布时会再次检查，先前选中的账号失效后需要重选。

权限由服务端按当前身份检查。共享令牌、自报作者名称和智能体请求不能代替个人登录。权限发生变化时，页面可能要求重新读取；不能通过保留旧页面继续写入。

## 一、保存会议原文并发布行动

1. 在 **会议与行动** 填写标题、会议日期和完整原文。日期未知可以留空。也可以导入 UTF-8 `.txt` 文件。
2. 点击 **保存会议原文**。原文创建后不能覆盖；需要修正原始记录时，另建一份会议记录并说明关系。完整原文、创建人、创建时间和 SHA-256 均保留。
3. 打开 **查看完整原始会议记录**，对照规则提取出的候选。当前只识别独立的 `TODO:`、`待办：`、`行动项：`、`Action item:` 和未勾选清单行；这是规则草稿，不是模型理解或人工确认。
4. 对每条候选点击 **补齐行动**。也可点击 **手动新增行动**，补充没有被规则识别的内容。系统不猜负责人、期限、交付物或验收条件；没有候选不代表没有待办。
5. 填写行动标题、有效个人负责人、交付物和“什么结果算完成”。期限未约定时保留为空，界面会明确显示“未约定”。可选择从 1 开始的原文起止行号；服务端只接受实际存在的行范围，并显示原文引用。
6. 核对内容后，点击 **核对并发布任务**，再提交表单中的发布操作。每条行动最多生成一张 `新建` 工单，带会议来源、原文哈希、引用位置和约定期限。发布不会触发自动处理。

会议草稿允许暂缺字段。撤回草稿必须填写原因，原行动及修改历史仍可查阅。已经发布的行动不再通过会议页直接修改、撤回或重复生成任务；进入关联任务按已有流程改派和推进。页面显示的当前负责人和任务状态来自关联工单，发布时的原约定保留在行动历史中。

参考知识项目可以保存会议与行动草稿；发布为任务前需要按现有项目流程进入开发维护工作流。

## 二、保存工作简报

在任务交接详情中填写 **结论、待决定、下一步、下一步协作人、期限**，点击 **保存简报新版本**。结论必填，其余信息未知时可暂留空。

“下一步协作人”是这一版简报中的协作约定，不会修改任务分配。简报也不会改变交接状态、复核人、任务状态或验收结果。已关闭任务仍可登记复盘说明，保存简报不会重新打开任务。

每个版本绑定当时的任务标题、完整正文、链接、分配信息、需求讨论、当前交接记录和已有会议来源。任务依据或当前交接发生变化时，旧版本显示 **来源已变化**。例如，交接从待接收变为已接收，原简报就需要重新核对。

来源变化不会覆盖旧简报。请展开 **查看最新完整来源**，对照原稿，使用 **保留草稿，核对最新依据** 后再保存新版本。旧版本及其完整来源一直保留；旧版不能因新版本保存而自动成为“已核验”。

简报来源是数据库中已登记的信息快照。它不执行 Git 检查、构建或测试，也不声称代码证据已经验证。

## 三、保存交付材料并核对内容覆盖

先从 **交付** 创建交付记录。新建操作会关联一张新建、未分配的工单，并保留原交付流程的执行限制；不会启动模型或自动处理。

在交付阶段的 **阶段手工材料** 中填写完整材料，点击 **保存材料新版本**。每次保存增加一个版本，旧手工材料、旧智能体产物及其来源不被覆盖。手工文字不带智能体运行来源，不能因此形成代码实现证据。存在关联的排队或运行中阶段时，需要等它结束后再保存手工材料。

随后在 **内容覆盖检查** 中：

1. 点击 **新增要求**，写清标题、需要覆盖的内容，以及是否为必要项。也可主动添加标准检查项，再按真实项目补充。
2. 选择本交付当前阶段的具体材料版本。尚未提供材料时留空，不伪造“已完成”。
3. 阅读材料并对照要求，点击 **核对这份材料**，完整说明核对了什么、依据是什么，保存本人的核对记录。
4. 要求、材料或相关来源有变化时，重新选择当前材料并再次核对。撤回要求需填写原因，历史不会删除。

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 缺少材料 | 尚未绑定材料 | 补充材料并选择具体版本 |
| 待人工核对 | 已绑定当前材料，还没有有效核对记录 | 阅读材料并登记核对依据 |
| 已核对材料 | 某位个人核对了当时的要求和固定来源 | 仍须完成原流程要求的技术验证、阶段复核和业务验收 |
| 来源已变化 | 材料、输入、实际来源运行或相关前置依据已变化 | 更新绑定并重新核对 |
| 已撤回 | 该要求已附理由退出当前清单 | 保留历史，必要时另建新要求 |

空清单不表示交付完整。标准检查项只帮助列出内容，不会自动核对或自动通过。即使必要内容均已核对，也只表示这份清单的材料核对完成，不能代替实际测试、安全检查、阶段复核、发布、业务验收或关单。

手工材料登记和内容核对可以在模型执行关闭的租户使用。它们不会开启宿主代码执行、模型、构建、测试或预览，也不解除原有执行和验收限制。

## 保存冲突、断网与草稿

页面会保留当前表单草稿。浏览器草稿按当前实例、租户、账号、项目和对象隔离，仍只属于这个浏览器会话；清除浏览器存储、结束会话或换设备可能失去尚未保存的草稿。重要原文应另有原始备份。

看到“尚未确认服务器是否保存”时，使用 **用原请求核对结果**。系统沿用原请求编号和完整内容，避免重复创建会议、任务或材料版本；取回回执后重新读取最新详情。不要为了重试修改请求内容。

看到记录或来源已变化时，先保留输入，刷新并对照最新内容，再明确重新绑定依据后保存。系统不会自动把旧稿套到新版本上，也不会静默放宽冲突检查。

全文不会为了提交成功而静默截断。当前请求大小有服务端上限；超限会明确失败并保留输入，不代表任何一部分已经保存。原始记录中的文字只作为资料，不会执行其中的命令。

## 当前范围

本轮支持个人填写、确定性候选提取、版本记录、来源追溯和同项目协作；不包含录音转写、模型自动提取、自动提醒、外发通知、跨租户共享或办公文件生成。会议原文导入目前仅支持 UTF-8 文本。实际运行、独立技术复核、人工确认和关单仍使用原有受控流程。
