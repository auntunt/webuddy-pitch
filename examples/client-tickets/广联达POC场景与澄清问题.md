## 六组可用的需求题

P1 是甲方明确举出的需求。P2–P5 是为验证 P1 而提出的边界场景，不是会议已确认的政策。P6 是结合会议中版本和回归诉求提出的后续候选。它们不必一次全部开发。

| 编号 | 给开发的需求题 | 涉及链路 | 要拿出的证明 |
|---|---|---|---|
| P1 | 增加按指定入围投标人报价平均值计算基准价的方法，并让专家看到所用规则 | 编标配置 → 持久化 → 交易接口 → 开评标 → 专家页面 | 同一项目的规则、参数和计算结果一致；旧方法仍通过 |
| P2 | 投标人数落在不同区间时，按约定选择参与计算的人数 | 人数来源 → 区间规则 → 计算 → 展示 | 每个区间边界两侧及边界本身有独立预期；人数不足的行为明确 |
| P3 | 规则发送后网络中断，重发不能重复覆盖；迟到旧版本不能覆盖新版本 | 发送 → 接收 → 数据库 → 重试/回执 | 接收记录和当前版本可核对；旧请求不改变已生效新规则 |
| P4 | 发布新政策后，新项目用新规则，既有项目按约定保留原规则 | 政策生效 → 项目规则快照 → 历史计算 → 导出 | 新旧项目分别得到预先确认的结果；历史记录可重现 |
| P5 | 某投标人资格或报价发生合法修正，重新计算后页面、接口和结果记录同步 | 资格/报价 → 有效集合 → 重算 → 页面/记录 | 入选名单、计算过程、规则版本与结果一致；越权修改被拒绝 |
| P6 | 同一需求用于另一项目时，保留共有规则，隔离项目差异 | 项目配置 → 业务规则 → 测试与发布 | 项目 A 的新行为通过，项目 B 的原行为不变；差异有需求依据 |

P3 的版本策略、P4 的生效口径、P5 的允许修改阶段都须先由业务方确认。若现有系统已有实现，应复用并测试，不另建重复机制。

## 主线的三级分解

| 一级场景 | 二级检查 | 三级输入或动作 | 验收证据 |
|---|---|---|---|
| 配置规则 | 创建、编辑、回读 | 选择新方法并填写人数；保存后重新进入 | HTTP 请求/响应、数据库字段、页面回读 |
| 配置规则 | 非法参数 | 空值、零、负数、非整数；适用范围外人数 | 界面与 API 拒绝；数据库无新增或错误覆盖 |
| 传递规则 | 正常传递 | 编标发布后在交易、开评标读取 | 同一项目 ID、规则版本、方法和参数逐项一致 |
| 传递规则 | 异常传递 | 缺字段、重复发送、旧版本迟到 | 明确失败或约定的幂等结果；数据库状态正确 |
| 计算结果 | 入选集合 | 正常报价、资格排除、并列、人数不足 | 固定输入名单、实际选入名单及排除依据 |
| 计算结果 | 数值精度 | 整数、小数、需要舍入的平均值 | 业务方提供的预期、实际值、差异；禁止由被测算法生成预期 |
| 专家使用 | 规则与结果展示 | 打开评分页面、刷新与再次读取 | 真实浏览器画面及 API 值一致；权限按既有规则 |
| 旧功能回归 | 旧计算方法与历史项目 | 用原数据执行原方法 | 修改前后结果对照，原回归保持通过 |

## 可以带去和甲方讨论的问题

先拿到前八项，就能固定首轮范围。其余问题按所选场景补充，不要求甲方一次回答全部。

1. 能否选一张已经做过、具备需求说明和验收记录的真实变更单，作为可对照的 POC？
2. 对应哪一份政策、哪一条规则？政策的计算示例能否作为独立预期？
3. “前 N 家”按报价、得分、抽签还是其他顺序确定？哪些投标人有资格进入候选集合？
4. 总投标人数指报名、实际递交、有效投标还是入围人数？人数在什么阶段固定？
5. N 是手填、按区间选择还是按公式计算？人数不足、并列和无人符合时分别如何处理？
6. 金额单位、保留位数、舍入方式是什么？先逐项舍入还是最后舍入？
7. 新规则替代原方法还是新增选项？已发布和正在评标的项目是否受影响？
8. 本次需要联动的仓库、服务、接口和数据库有哪些？哪个环境能运行完整链路？
9. 编标、交易、开评标各由谁负责？真实接口暂不可用时，哪些检查只能标为契约验证？
10. 规则传递的项目/标段标识、版本、必填字段和错误码是什么？现有幂等与顺序约定是什么？
11. 哪一端是规则来源？专家页面展示文字和实际计算是否读取同一份规则？
12. 资格变化、撤回投标或报价修正后，允许谁在什么阶段重算？历史结果怎样保留？
13. 是否还影响评分公式、排名、报告、导出或对外接口？请给一个预期结果样本。
14. 哪些原有用例绝不能退化？现有测试和历史缺陷清单能否在批准环境内复用？
15. 有没有“单元测试通过，联调或人工测试才发现”的同类问题，可作为盲测场景？
16. 需求中哪些地方由业务确认，哪些由开发决定？谁确认预期结果，谁做最终验收？
17. 目标运行环境是否涉及 Windows、Java/.NET、达梦等？请区分实际目标与会议设想。
18. 源码、日志、测试数据和模型调用分别允许在哪个环境处理？是否有可用的脱敏数据？
19. 现有 Cursor＋测试＋人工 Review 的操作步骤与耗时如何记录，才能与 POC 做同范围比较？
20. 人工复核时，能否逐项标记有效发现、误报、未判断以及人工另行发现的问题，并记录实际分钟数？
21. 首轮达到哪些结果就算通过？哪些必须人工确认，哪些只要求自动报告？
