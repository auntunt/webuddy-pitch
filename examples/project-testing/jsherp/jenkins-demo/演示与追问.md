# 私有 Git + Jenkins + ERP 演练

这是公开 JSHERP 的隔离演练，不是怀柔客户项目验收。使用 Apache-2.0 许可的既有导入快照，保留 LICENSE；不声称是最新上游版本。代码、数据库、Git 与 Jenkins 都在本机 Docker 演示环境；没有修改客户系统。

## 本次暂定需求

销售退货发生退款时，必须填写退款说明。复用已有备注字段，不改账务、库存审核、付款和权限规则。网页和接口不能给出相反的答案；接口绕过页面提交时仍须校验；保存后数据库与重新打开的页面保留说明。

**以下是演示假设，待演示参与人确认后才能作为正式业务要求：**

- 只约束销售退货，且本次退款金额不为零；不限制赊账退货的零退款。
- 新建、修改均检查；历史记录可查看，编辑时按当前规则补齐。
- 去除首尾空白后，说明长度为 5—200 个 Unicode 字符；不接受纯空白。
- 原有单账户 12.50、多账户 7.25+5.25、保存、回读、防重复、未登录拒绝必须保持。
- 不涉及财务过账、库存审核、附件强制上传或正式生产发布。

## 分轮提问

每轮允许“待确定”。未确认的必需规则应阻止开工，不能让 Agent 自动选择推荐项后当成客户确认。终端的答案应写入已有开发会话，网页可读同一份修订。

| 轮次 | 问题 | 可选方向及影响 |
|---|---|---|
| 业务目标 | 退款说明是为了财务追溯、售后分类还是审批？ | 决定是否只需文字，还是必须分类/关联原销售单 |
| 业务目标 | 哪类单据适用？ | 仅销售退货／采购退货也适用；本轮先只演练前者 |
| 业务目标 | 零退款但有退货，需要说明吗？ | 不影响资金／所有退货都要求；不能擅自禁止赊账退货 |
| 规则 | 说明最少和最多多长？中文、表情如何计数？ | Unicode 字符；不能前端按字节、后端按另一个口径 |
| 规则 | 首尾空格、换行、全角空格怎样处理？ | 统一空白规则；空白不能被当作真实说明 |
| 规则 | 老单据没有说明，是否可以看、打印、编辑？ | 查看不拦；编辑补齐／存量豁免要明确 |
| 规则 | 批量导入和外部 API 是否也受约束？ | 如果共用保存入口，应检查；未覆盖的入口明确列出 |
| 范围 | 是否需要新的原因分类、附件、审批？ | 与本轮纯说明需求分开；不能悄悄扩成审批系统 |
| 范围 | 是否影响导出、查询、手机界面？ | 明确保持与新增项，未验证部分保留缺口 |
| 权限 | 谁可以填写、修改与最终确认？ | 沿用现有角色；开发 Agent 不冒充业务验收人 |
| 执行 | 由 Webuddy 系统执行，还是 Cursor/终端本地执行？ | 选择与确认修订绑定；确认本身不启动开发 |
| 执行 | 当前目录是不是登记项目，HEAD 是否为固定起点？ | 不匹配先解释差异；不强制清空未提交代码 |
| 执行 | 模型能接收哪些材料，走哪个通道？ | 代码本地保存不代表模型请求完全不出域 |
| 测试 | 谁给出预期？ | 业务确认样例／现有规则；不由被测实现生成正确答案 |
| 测试 | 哪些历史行为绝不能变？ | 单/多账户、金额、防重复、未登录拒绝与零退款 |
| 测试 | 缺数据库、测试失败、CI取消分别怎么办？ | 补条件／返修／重新执行；不能都显示通过 |
| 复核 | Leader 看哪些内容？ | 实际差异、规则来源、逐项证据与缺口 |
| 合并 | Leader 通过后谁操作？ | 负责人再次确认合并；本地合并不代表远端已推送或发布 |
| 交付 | 浏览器或终端超时后怎样知道是否成功？ | 先读任务/候选/合并回执，不盲目重复提交 |
| 价值 | 本轮比现有工具节省了什么？ | 记录实际澄清、复核、补测与返修时间；暂不填写收益数字 |

## 可照着执行的演示顺序

1. 展示项目来源、固定基线和本地 Git，解释平台内置 Git 工作区管理与正式远端的边界。
2. 输入需求，分轮回答上述关键问题。演示中没有真实业务方答案的内容保持“演示假设”。
3. 人在终端确认当前修订，明确选择系统执行或本地执行。展示目录、远端和版本预检。
4. 查看改前结果；新增约束在旧版失败是预期缺口，不是旧功能回归。
5. 展示 UI/API 改动与受影响旧功能；运行精确候选 Jenkins 构建。
6. 打开逐项测试报告、HTTP 与数据库依据、浏览器原图；区分实测与代码 Review。
7. 打开 Webuddy 网页交付依据，或 MCP `webuddy_delivery_get` 读取同一份产出与方案。只读包不自行宣布当前可合并。
8. 展示当前候选必需 CI。失败、取消、未知仓库/提交时保持阻断；不能借 Webuddy 自身 CI 代替 ERP CI。
9. Leader 独立复核，负责人再次明确确认合并。演示者若不是指定真人，只展示入口，不代签。
10. 核对本地合并回执、正式远端和发布记录，分别说明；最后记录人工投入与未覆盖项。

## 现场分支卡

| 现场变化 | 应显示 | 不能做 |
|---|---|---|
| 把说明下限从5改成10 | 原确认失效，重新确认和复验 | 复用旧绿灯 |
| 关闭测试数据库 | 验证受阻及根因 | 反复修改业务代码 |
| Jenkins取消或运行中 | 必需CI未满足 | 用上一次不同提交成功放行 |
| 页面输入合法、直接API输入非法 | API拒绝且数据库不新增 | 只验证前端必填 |
| Leader批准后改代码 | 旧依据不支持新候选 | 将前后两版结果拼成通过 |
| 负责人网络断开后重连 | 查询已有回执 | 重复合并或重复建单 |
